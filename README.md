# Athena · IDE для 1С

Локальная среда для исследования файловой выгрузки 1С: дерево метаданных, редактор BSL, связи вызовов, поиск, справка платформы, автодополнение и наборы изменений. Подключаются Ollama и OpenAI-совместимые серверы моделей.

**Статус: прототип в активной разработке.** Доступны вопросы по конфигурации с инструментами чтения, агент с отдельными наборами предложений и генератор документации по проекту, модулю или выделенному коду. Добавлены память результатов инструментов и завершение при повторных обходах. Локальные механизмы проверены тестами; качество конкретной модели и корректность изменений в 1С требуют отдельной проверки. Подробнее — в [известных проблемах](docs/KNOWN_ISSUES.md).

## Быстрый запуск

Основное окружение — Windows x64 и Python 3.12 с Tcl/Tk. Для учебного примера 1С не требуется; для выгрузки и загрузки нужна установленная платформа и доступ к информационной базе.

```powershell
git clone https://github.com/kringetos/athena-1c.git
Set-Location athena-1c
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m athena.server
```

Откройте `http://127.0.0.1:8765/` и пройдите первоначальную настройку. Справка запускается отдельно на порту 8767. После создания `.venv` также можно использовать `Start.cmd`. Для другого порта: `python -m athena.server --port 8766` выбранным интерпретатором.

Для просмотра откройте каталог с `Configuration.xml` или учебный проект `examples/demo`. Полная последовательность установки, настройки 1С и моделей, GPU, резервного копирования и обновления приведена ниже.

## Создание документации в Athena

В **Документация → Git-проекты** можно подключить несколько репозиториев с документацией и кодом. Их материалы учитываются в ответах AI и агента. Доступны получение изменений, обновление каждую минуту, редактор, копирование текущей выгрузки 1С, просмотр diff, коммит выбранных файлов и push. Требуется Git; доступ к закрытым репозиториям настраивается через Git Credential Manager или SSH. Подробности — в [руководстве](docs/USER_GUIDE.md#git-проекты).

Документы для агента загружаются отдельно: **Документация → База знаний агента → Загрузить и индексировать**. Поддерживаются MD/TXT/PDF/DOCX; локальные эмбеддинги строятся автоматически. Проверенные инструкции можно отметить как **Обязательные правила проекта** — они закрепляются в каждом запросе агента. Подробности и ограничения — в [руководстве пользователя](docs/USER_GUIDE.md).

1. В настройках AI укажите модель и API-ключ либо подключите Ollama. Для внешнего API включите разрешение передачи кода выбранному серверу.
2. Откройте файловую выгрузку и дождитесь индексации.
3. Выберите **Документация → Создать документ**. Для описания фрагмента откройте BSL-модуль в **Коде**, выделите текст в редакторе и нажмите **Документировать**.
4. Выберите тип и область, задайте название и нажмите **Создать документацию**.
5. Проверьте черновик, при необходимости отредактируйте на вкладке **Markdown**, сохраните или скачайте `.md`.

Скилл Documentation Generator и шаблон уже включены в приложение; устанавливать их отдельно не требуется. Документы хранятся в `.athena/documents` отдельно от исходников. При неполном контексте показывается предупреждение; документация не считается автоматически проверенной в 1С. После перезапуска сервиса API-ключ вводится заново.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

На подготовленном состоянии проекта проходит 186 тестов. Интеграционные проверки с тестовой моделью не подтверждают качество настоящей модели. Реальные выгрузки клиентов и учётные данные для тестов не нужны.

## Что не входит в Git

`.athena`, `.venv`, выгрузки рабочих конфигураций, SQLite, модели, GPU-библиотеки, журналы и локальные настройки игнорируются. В `examples` находится только небольшой учебный проект. Данные хранятся рядом с клоном, поэтому заранее выберите диск с запасом места.

Изменения агента сохраняются в отдельный набор. Перед загрузкой в 1С их просматривает пользователь; обновление конфигурации базы данных выполняется в самой 1С. Не используйте рабочую базу клиента для разработки и не выставляйте локальные порты в интернет.
