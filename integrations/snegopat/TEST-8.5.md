# Реальный тест Снегопата на 1С 8.5

Дата: 15 октября 2026. Результат: **Alpha19 не запускается на 8.5.1.1522 x86**.

## Проверенные компоненты

- Установленный `1cv8.exe`: FileVersion/ProductVersion 8.5.1.1522, PE machine 0x14c (x86).
- [Core.As Alpha 1.0.2.4](https://github.com/infostart-hub/core_as_loader/releases/tag/Alpha_1_0_2_4): `core-as-1-0-2-04.zip`.
- [Снегопат Alpha19](https://github.com/infostart-hub/snegopat_modul/releases/tag/Alpha19): `snegopat-Release-2022-03-03.zip`.

SHA-256 скачанных архивов:

```text
Core.As: FC5471B3D67A820E2B2F556904EE0CCEBC435EE9F973B8423282030461349D4B
Снегопат: 464256EA84009D66F2D177CE92CB128479BA634DA6A493A93AEF579410710FDE
```

## Что выполнено

1. Архивы распакованы в игнорируемую Git папку `.athena/integrations/test-8.5/runtime` на диске с данными Athena.
2. Через `CREATEINFOBASE` создана отдельная пустая файловая база `test-8.5/empty-base`. Результат создания: 0, журнал подтверждает успех. Пользовательская база не открывалась.
3. При отсутствии других процессов 1С запущен `starter.exe`, затем установленный `1cv8.exe DESIGNER /F <тестовая база>`. В тестовом `options.ini` включён `LogLevel = Diagnostic`.
4. В модулях тестового процесса обнаружены `inject.dll`, `core_as.dll` и `snegopat.dll` из тестовой папки. Конфигуратор оставался работающим, с заголовком «Конфигуратор — Конфигурация».
5. Снегопат записал ошибку при препроцессинге `v8api/process.v`, строка 5. Затем записал «Не удалось подготовить внешнее API». [Сохранённый журнал](test-8.5-error.txt).
6. После фиксации результата тестовые процессы стартера и Конфигуратора остановлены. В каталог платформы файлы не устанавливались. Автозапуск и настройки пользовательской базы не менялись.

## Почему поле не появилось

Исходный файл API в скачанном выпуске содержит:

```text
#if ver < 8.2.19 | (ver > 8.3.0 & ver < 8.3.4) | ver >= 8.3.20
#err Unsupported version of 1C - Эта версия 1С не поддерживается!
#endif
```

На этом этапе загрузка остановилась. `AthenaTextInputBridge.vbs` и `AthenaTextInput.js` в реальном Конфигураторе не исполнялись. Визуальная проверка окна ввода не выполнена, поскольку рабочий движок Снегопата не загрузился.

Этот результат относится к указанным выпускам и установленной 32-битной платформе. Он не доказывает, что любые сторонние форки принципиально не могут поддерживать 8.5. Для продолжения нужен порт нативного API под точный релиз; подмена версии или снятие запрета совместимость не обеспечивает.

## Проверка подготовленного прототипа

JScript проверен отдельно с подставным API: регистрация макроса, отсутствие моста, передача предыдущего текста, сохранение значения при пустом вводе и отмене. Проверки прошли. 32-битный Windows Script Host успешно разобрал VBScript-функцию; `InputBox` в этом тесте не вызывался. Эти проверки не заменяют выполнение аддина в 1С.

## Продолжение: причины и частичные исправления

Исследована отдельная копия `patched-runtime`; исходный скачанный выпуск сохранён.

1. Изменены зависимости `core83.dll` → `core85.dll` и `wbase83.dll` → `wbase85.dll`. Это реальные имена библиотек установленной платформы.
2. В `core85.dll` функция `load_module_wstring` получила дополнительный параметр `bool`: в экспериментальной декларации добавлены аргумент с умолчанием `false` и соответствующее экспортируемое имя.
3. Конструктор `Rect` экспортируется с параметрами `long` (`JJJJ`) вместо `int` (`HHHH`). В Windows x86 оба имеют размер 32 бита; имя в декларации исправлено.
4. `calcShadowRect` теперь возвращает `void` и принимает выходной `Rect&`; декларация и экспорт исправлены. `calcWindowTopRightPos` перешла в пространство имён `wbase`; исправлено имя.
5. Для этой отдельной копии проверка версии ограничена точным релизом 8.5.1.1522 x86; остальные версии отвергаются. Это не разрешение использовать её в рабочих базах.

Скрипт `audit_exports.py` читает PE-таблицы экспортов без загрузки DLL. Проверено 200 именованных привязок активных ветвей API: после сопоставления новых DLL до исправлений найдены 196, после исправлений — 200. Системная `Dbghelp.dll` проверяется в 32-битной системной папке. [До](export-audit-before.json), [после](export-audit-after.json). Этот аудит не проверяет таблицы виртуальных методов, размеры объектов и жизненный цикл 1С.

Экспериментальный [патч API](alpha19-8.5.1.1522-x86-experimental.patch) проверен командой `git apply --check --unidiff-zero` на исходной копии Alpha19. Он сохраняет кодировки и окончания строк исходных файлов. Патч устраняет ошибки привязок, но сам по себе не запускает меню и макросы. Применять его следует только к отдельной тестовой копии с `--unidiff-zero` из каталога модуля Снегопата.

После исправлений реальный журнал подтверждает регистрацию внешнего API модуля (360 сущностей). Однако штатный `run()` не был вызван. Диагностический вызов из `main()` дал `Null pointer access` в `getProfileService()` ([журнал](test-8.5-bootstrap-error.txt)). В одном запуске трассировка показала, что в `main()` сам `currentProcess()` ещё равен `null`; через 500 мс в обработчике таймера он уже доступен. В другом повторном запуске он был доступен уже в `main()`, что указывает на зависимость от момента инициализации. Отложенная инициализация успешно прошла этапы `symbols`, `paths`, `profile`, `frame` и завершила `run()` ([захваченная трассировка](deferred-bootstrap-output.txt)). [Диагностический патч запуска](alpha19-8.5.1.1522-bootstrap-experimental.patch) также проверен через `git apply --check --unidiff-zero`; это эксперимент, а не готовое восстановление всех событий.

После полного запуска на пустой базе штатное окно по Ctrl+Shift+M не появилось, профиль `snegopat.pfl` не был создан. Отложенный `run()` сам по себе не подтверждает правильное прохождение ранних событий открытия профиля, создания основного окна и последующих пакетов аддинов. Для полного порта нужно восстановить эти этапы и проверить внутренние интерфейсы и перехваты редактора. Конкретное изменение класса окна или таблицы виртуальных методов пока не доказано; подмена их адресов вслепую не выполнялась.

Отдельно проверен небольшой [модуль Core.As](../core-as-text/README.md), открывающий стандартный VBScript-диалог ввода внутри процесса `1cv8.exe` без частного API 1С. Проверены заполнение через API доступности и подтверждение Enter, затем продолжение работы Конфигуратора. Прямая имитация набора символов автоматизацией результата не дала; ручной набор пользователем отдельно не подтверждён. Этот результат не доказывает полноценную совместимость Снегопата.
