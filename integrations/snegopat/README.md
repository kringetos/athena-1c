# Минимальное текстовое поле для Снегопата

**На 1С 8.5.1.1522 x86 проверен реальный запуск: Снегопат Alpha19 не запустился.** Core.As 1.0.2.4 подключился к отдельному тестовому Конфигуратору, загрузил DLL Снегопата, но подготовка API остановилась с ошибкой `Unsupported version of 1C`. В выпуске Alpha19 файл `v8api/process.v` явно запрещает версии от 8.3.20. Текстовое поле в 8.5 не открылось: до исполнения аддинов дело не дошло. [Отчёт о тесте](TEST-8.5.md), [исходный журнал](test-8.5-error.txt).

Продолжение проверки: подготовлен экспериментальный частичный порт API. Все 200 проверяемых имён экспортов найдены в 8.5; отложенный запуск завершает `run()`. Но штатное меню и макросы пока не появились, поэтому полноценная работа Снегопата по-прежнему не подтверждена. Для минимального поля отдельно проверен [прототип на Core.As](../core-as-text/README.md), без полного Снегопата и его частного API 1С.

## Что подготовлено

- `AthenaTextInputBridge.vbs` — собственная маленькая VBScript-библиотека, которая вызывает стандартный `InputBox`.
- `AthenaTextInput.js` — JScript-макрос **«Athena: текстовое поле»**. Находит мост через API аддинов и передаёт ему заголовок, подсказку и прежний текст.
- `Test-Compatibility.ps1` — читает версию и PE-разрядность `1cv8.exe`, ничего не запускает и не загружает.

Это **однострочный модальный диалог Windows, запускаемый аддином Снегопата**, а не панель, прикреплённая к редактору 1С. Введённый текст запоминается только на время загрузки скрипта; при повторном открытии показывается снова. «Отмена» или пустой ввод сохраняет прежнее значение. Нет вызовов модели, сети, вставки текста в редактор, изменения метаданных или записи файла.

## Проверка платформы

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\integrations\snegopat\Test-Compatibility.ps1 -Platform "C:\Path\To\1cv8.exe"
```

`not_declared_supported` означает, что исходный проект не заявляет этот релиз. `candidate_requires_matching_build` — только кандидат в диапазоне README, не доказанная совместимость конкретной сборки. Не обходите результат заменой номера версии: нативный API Конфигуратора зависит от его версии и разрядности.

## Запуск при наличии работающего Снегопата

Выполнять только на тестовом Конфигураторе со сборкой Снегопата, уже проверенной для установленного релиза. Откройте список аддинов Снегопата (в исходном проекте Ctrl+Shift+M), используйте загрузку внешнего скрипта:

1. Загрузите `AthenaTextInputBridge.vbs`.
2. Загрузите `AthenaTextInput.js`.
3. Вызовите список макросов (Ctrl+M), выберите **«Athena: текстовое поле»**. Также доступен макрос по умолчанию при открытии аддина.
4. Введите текст, закройте диалог и откройте его снова: прежний непустой текст должен сохраниться.
5. Проверьте «Отмена»; исходный модуль и конфигурация должны остаться прежними.

Файлы сохранены в UTF-8 с BOM для кириллицы. Разрешение VBScript/JScript в системе и работа загрузчика должны быть проверены на целевой машине; аддин сам не включает системные компоненты и не меняет настройки Windows.

## На каких API основан прототип

Метаданные `//engine`, `//uname`, регистрация `SelfScript.self["macros..."]`, `getDefaultMacros`, `global.connectGlobals`, поиск `addins.byUniqueName(...).object()` следуют примерам проекта:

- [RegExpEditor.js](https://github.com/infostart-hub/snegopat_modul/blob/master/addins/RegExpEditor.js) — макросы и подключение глобального API.
- [std/vbs.vbs](https://github.com/infostart-hub/snegopat_modul/blob/master/addins/std/vbs.vbs) — VBScript-движок и вызов библиотеки через объект аддина.
- [v8api/window.v](https://github.com/infostart-hub/snegopat_modul/blob/master/v8api/window.v) — примеры зависимости оконного API от версии платформы.

Чужие DLL, стартер, внешние обработки и полный исходный проект в комплект не включены. Проверка скрипта с тестовым API не доказывает работу в Конфигураторе. Для вашей 8.5 нужна совместимая сборка Снегопата либо перенос его нативных адаптеров; одного удаления проверки версии недостаточно.
