# Известные ограничения и проверенный статус

Git-интеграция поддерживает клоны и обычные ветки origin. Автоматическое разрешение конфликтов, force-push, подмодули/LFS, создание репозитория на сервере и Git-поиск по эмбеддингам не реализованы. Цикл clone/fetch/commit/push проверяется на временных локальных репозиториях; авторизация Git-хостингов и качество ответов настоящей модели требуют отдельной проверки. Для крупных выгрузок используйте внешний Git: индекс ограничен 20 МБ и 2000 файлами. Предложения агента отправляются через проверенную актуальную выгрузку; автоматического применения наборов в Git нет.

## Агент: прежние сбои и текущие изменения

Точный запрос `Создай справочник Номенклатура с реквизитом цена` после расширения разбора проверен через интерфейс на «Учет1»: 1 изменение, реквизит `цена` типа Число(15,2), статус `prepared`, 4 инструмента, 0 обращений к модели, около 1 секунды. Импорт для этой проверки не запускался. Пять старых пустых наборов агента перенесены в восстанавливаемый архив. Полный набор: 254 теста, 1 пропущен.

16.10.2026: запрос `Создай справочник Номенклатура с реквизитом цена` раньше не попадал в прямой исполнитель из-за отсутствующего типа: одна попытка дала HTTP 401, другая завершилась без прогресса. Добавлены реквизиты без явно заданного типа и формулировки `типа Число(15,2)`, списки через «и». Неуказанные типы определяются видимыми значениями по умолчанию: цена/сумма/количество и другие перечисленные числовые имена — Число(15,2), даты — Дата, признаки активности — Булево, остальные — Строка(100). Явные типы сохраняются. Пустые наборы терминальных неудачных запусков архивируются с возможностью восстановления, история и ошибка сохраняются; наборы с предложениями не архивируются.

После перезапуска сервера прямой путь проверен через интерфейс на конфигурации «Учет1»: запрос `Создай справочник Тест без реквизитов` дал один объект в наборе со статусом `prepared`, успешную проверку и пакет с `Catalogs/Тест.xml`. Выполнено 4 инструмента, 0 шагов модели, около 2 секунд. Пакет в базу 1С не загружался. Полный набор после изменения: 249 тестов, 1 пропущен.

16.10.2026: повторный запуск DeepSeek после изменения инструкций снова завершился пустым набором: 22 чтения/поиска, без `create_object`. Для однозначных запросов создания добавлен прямой исполнитель без вызова LLM: проверка имени, `create_object`, `validate_changes`, `prepare_changes`. Поддерживаются один новый справочник/документ без собственных реквизитов и явно типизированные реквизиты вида `ИНН: Строка(12), Сумма: Число(15,2)`. Разбор охватывает весь запрос; дополнительные требования, несколько действий и неоднозначные формулировки передаются модели целиком. При включённых обязательных правилах проекта также используется модель, чтобы не обходить правила. Прямой путь сохраняет проверки контекста, отмены, версии набора и ограничения инструментов, не требует подключения LLM и не загружает пакет в 1С. В режиме предложений три шага без новых результатов прекращают повторный обход; изменение размера страницы или поисковой строки при тех же результатах не считается прогрессом. Пустой или невалидный набор больше не помечается успешно завершённой задачей. Это не даёт гарантии выполнения произвольных запросов моделью или при сбое файловой системы/платформы.

16.10.2026: уточнены системные инструкции для создания метаданных: однократная проверка имени, `create_object` для нового справочника/документа, затем `validate_changes` и `prepare_changes`. Завершение обзора теперь отделено от выполнения изменений. Подсказки при повторных результатах в режиме предложений направляют к созданию или правке, а не только к чтению BSL. Итог по лимиту не должен трактовать временное отключение инструментов как отсутствие возможности создания. Регрессионный сценарий с тестовой моделью проверяет подготовку справочника без реквизитов после повторных списков при контексте 18000 символов; выполнение этого сценария настоящей DeepSeek после изменения инструкций ещё не подтверждено.

16.10.2026: подключён гибридный поиск агента, исправлены диапазоны и продолжения чтения, добавлены покрытие и диагностика. Повторы и найденные формулы больше не вызывают преждевременного отключения инструментов. Подробности, ограничения и команда стенда: [AGENT_RELIABILITY.md](AGENT_RELIABILITY.md). Реальная проверка двух локальных моделей выявила HTTP 500 из-за отсутствующего `llama-server.exe` в установленном Ollama; качество моделей этим запуском не оценено.

Поиск расчётов (15.10.2026): сокращение истории теперь сохраняет фрагменты исходников, методы и номера строк вместо заглушки о повторном чтении. Пропуски и усечение обозначаются явно. Поиск возвращает короткие фрагменты трёх первых методов; остальные найденные методы агент должен прочитать отдельно. Поисковые чтения не удерживают блокировки статуса и отмены; результат при смене проекта отклоняется.

Для проектов до 2000 методов и 8 млн символов сериализованных методов используется временный FTS-индекс только текущего снимка в памяти; более крупные проекты используют прежний общий индекс. На сохранённом проекте из 23 модулей поиск «Сумма» занял около 0,02 с. Это время поиска, а не полного ответа модели. Проверки сохранения доказательств после сокращения истории используют имитацию модели; качество ответа внешней модели после исправлений требует отдельного повторного запуска. Полный набор: 211 тестов пройдено.

До текущих исправлений в рабочей конфигурации с подключением `~deepseek/deepseek-v4-flash-latest` в журналах наблюдались два случая:

1. **«Создать документ Поставка с реквизитом количество и товар».** Агент выполнил 24 чтения/поиска за 12 шагов и достиг лимита; набор остался пустым. Тогда `create_object` и `update_new_object` существовали в общем API, но не предоставлялись модели.
2. **«В документе счет цена после ввода умножалась на 2».** Агент выполнил 22 поиска и 2 чтения объектов за 12 шагов, без `read_module` или `edit_module`; набор остался пустым. Полная причина поведения настоящей модели не установлена.

Сейчас создание справочников и документов подключено к режиму предложений. Добавлены кеш успешных чтений и компактная память при сокращении истории. Прежнее завершение после двух раундов без новых фактов заменено подсказкой перейти к чтению кандидатов; общие бюджеты остаются конечными. Журнал показывает страницы, повторные чтения, диапазоны, фактический режим поиска и причины завершения. Режим исследования при остановке не сообщает о сохранённых предложениях. Метаданные доступны через полный перечень объектов с постраничной навигацией; общие списки и структурные счётчики вопросов обрабатываются отдельно от top-N поиска по коду.

Эти механизмы покрыты автоматическими тестами. Это не является подтверждением успешного выполнения двух прежних задач настоящей моделью. Следующий шаг — повторить их в тестовой базе с реальным подключением и проверить фактическую разницу. Набор создаётся при запуске предложений и всё ещё может остаться пустым; наличие набора или текст модели не подтверждают правку.

## Что проверено тестами

Проверены изоляция проекта, хеши и ревизии, BSL-разбор, подготовка пакетов, повторные вызовы, остановка, протоколы моделей, запрет поздних действий и другие локальные механизмы. Актуальные результаты проверки надёжности приведены в [AGENT_RELIABILITY.md](AGENT_RELIABILITY.md). Полный цикл интерфейса «чтение → правка → проверка → пакет → разница» проверен с **тестовой моделью** на учебном проекте.

Генератор документации проверен автоматическими тестами: захват выделения с позициями UTF-16, переводами строк и черновиком, хеши, отмена, отклонение устаревшего контекста, сохранение и HTTP-маршруты. Интерфейс «выделить → создать → отредактировать → сохранить → скачать» проверен с тестовой моделью. Качество генерации настоящей моделью и успешность двух пользовательских задач выше не подтверждены. Нельзя писать в релизе «агент полностью работает» только на основании автоматических тестов.

## Остальные границы

- 16.10.2026: устранено ложное расхождение после импорта справочника с реквизитом в 1С 8.5. Платформа дописывает `FillFromFillingValue=false`, `FillValue xsi:nil=true` и `Use=ForItem` для реквизита справочника. Проверки одиночного объекта и набора используют общее сравнение с нормализацией этих значений по умолчанию; иные значения, неизвестные свойства, UUID и параметры типов остаются значимыми. Сохранённая обратная выгрузка «Учет1» со справочником `Тест` и числовым реквизитом `Цена` прошла повторную проверку без новой загрузки в 1С.

- Создание метаданных поддерживает справочники и документы; изменение структуры существующего объекта, формы и остальные типы — отдельная будущая работа.
- Разбор ANTLR выявляет синтаксические ошибки, но не заменяет проверку конфигурации платформой 1С, типов и бизнес-логики.
- Часть связей вызовов остаётся неразрешённой или предположительной (`candidate`).
- Поиск агента использует гибридный поиск при готовом смысловом индексе; иначе явно сообщает о лексическом режиме. Точный поиск имён остаётся отдельным.
- Контекст ограничивается символами, не точным токенизатором модели. При сокращении удаляются старые пары вызов/результат; компактная память сохраняет часть проверенных фактов в пределах своего лимита.
- Генератор документации использует заранее собранный статический контекст без инструментального обхода. Обзор крупного проекта может быть неполным; смысловая точность автоматически не проверяется. Фрагмент или модуль, не помещающийся целиком, отклоняется с предложением сузить область.
- Git-подключение остаётся отключённой заглушкой. Импорт MD/TXT/PDF/DOCX в базу знаний реализован; OCR сканов и извлечение иллюстраций не поддерживаются. Включённые правила ограничены 12000 символов суммарно и передаются на каждом шаге, но фактическое соблюдение моделью требует проверки результата.
- Остановка агента прекращает следующие действия, но текущий HTTP-запрос может завершиться только по ответу/тайм-ауту.
- Загрузка пакета платформой не гарантирует атомарность. При ошибке после начала записи требуется проверка результата; автоматический повтор запрещён.
- Обновление конфигурации базы данных выполняется в 1С пользователем, не агентом.
- Несколько IDE-процессов с общей `.athena` не являются штатным режимом совместной работы. Синхронизация части наборов основана на внутрипроцессных блокировках.
- Версия справки, режим совместимости конфигурации и выбранный сервер/клиентский контекст требуют внимания разработчика; наличие статьи в справке не означает доступность вызова в любом модуле.
