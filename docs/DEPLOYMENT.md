# Развёртывание Athena

## Что развёртывается

Локальное приложение: Python-сервис, HTML/CSS/JavaScript-интерфейс и SQLite. Node.js, Java и Docker для обычного запуска не нужны. Генерированный ANTLR-парсер уже входит в репозиторий.

Основной сценарий развёртывания — Windows x64 с Python 3.12. Автоматические выгрузка и загрузка требуют установленной платформы 1С и доступа к соответствующей информационной базе. Просмотр учебного примера не требует 1С. Для выбора папок используется `tkinter`, поэтому установите обычный Python с поддержкой Tcl/Tk.

CPU достаточно для просмотра, лексического поиска и локальных подсказок. GPU необязателен. Для работы с моделью потребуется отдельно установленный Ollama/совместимый локальный сервер либо доступ к внешнему API; приложение не устанавливает генеративную модель автоматически.

## Установка из Git

1. Склонируйте репозиторий **на диск с запасом места**. Данные `.athena` создаются рядом с исходниками. Большие конфигурации, повторные выгрузки, индексы и GPU-библиотеки могут занять десятки гигабайт; универсальной оценки времени и размера нет. Репозиторий закрытый: для клонирования нужен доступ GitHub, выданный владельцем.

```powershell
git clone https://github.com/kringetos/athena-1c.git
Set-Location athena-1c
```

2. В PowerShell перейдите в корень клона и создайте отдельное окружение:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

3. Запустите сервис:

```powershell
.\.venv\Scripts\python.exe -m athena.server
```

Либо откройте `Start.cmd`: он предпочитает `.venv` проекта, проверяет основные зависимости и при необходимости устанавливает их. Если `.venv` отсутствует, остаётся прежний поиск доступного Python. Для переносимого развёртывания используйте описанное выше окружение, а не Python из Codex на машине автора.

Адрес IDE: `http://127.0.0.1:8765/`. Сервис справки автоматически запускается отдельным процессом на `http://127.0.0.1:8767/`. При первой установке IDE открывает мастер `/setup`.

Дополнительные варианты запуска:

```powershell
# Без открытия браузера
.\.venv\Scripts\python.exe -m athena.server --no-browser

# Если 8765 занят
.\.venv\Scripts\python.exe -m athena.server --port 8766

# Открыть уже существующую файловую выгрузку
.\.venv\Scripts\python.exe -m athena.server --project "D:\1CExports\MyConfiguration"
```

В каталоге выгрузки должен быть `Configuration.xml` и соответствующие XML/BSL-файлы. Файлы `.cf` и база 1С не являются файловым проектом для просмотра. Расширение выбирается в подключении к 1С, если работа ведётся с расширением конфигурации.

## Первоначальная настройка

1. В мастере задайте режим нагрузки: «Комфортная работа» или «Максимальная скорость». Начните с CPU, если GPU ещё не настроен.
2. Выберите фактический путь к `1cv8.exe` установленной версии платформы. Проверка пути доступна в интерфейсе.
3. Настройте подключение AI: адрес, модель, тайм-аут и размер контекста. Проверьте соединение и список моделей. Такая проверка ещё не подтверждает качество генерации или поддержку инструментов выбранной моделью.
4. Разрешение передачи кода внешнему серверу включайте только для выбранного подключения, если это допустимо для проекта. Локальный поиск и локальные подсказки не требуют этого разрешения.
5. Сохраните настройки и откройте учебный пример или файловую выгрузку. Для автоматической выгрузки используйте «Выгрузить из 1С», создайте профиль и введите необходимые учётные данные в интерфейсе.

API-ключ и пароль 1С хранятся в памяти процесса, не в Git. После перезапуска вводятся заново. Профили, адреса и пути сохраняются локально в `.athena`.

## Необязательные функции

**Синтаксис-помощник:** импортируется из файлов `.hbk` установленной платформы рядом с `1cv8.exe`. Файлы справки 1С не входят в Git; для каждой машины нужна собственная установка платформы. Версии справки изолированы.

**Локальные эмбеддинги:** модель E5 скачивается при подготовке смыслового индекса. Первый расчёт большого проекта может быть длительным; последующие открытия используют кеш. Смысловой индекс запускается и приостанавливается отдельно. Лексический поиск работает без эмбеддингов.

**GPU:** кнопка мастера создаёт отдельное `.athena/gpu-runtime`, устанавливает библиотеки и проверяет вычисление на CUDA. Нужны Windows x64, Python 3.11+, NVIDIA и совместимый драйвер. Текущая реализация проверяет поддержку CUDA 13+ драйвером; системный драйвер автоматически не обновляется. До успешной проверки используйте CPU.

**Агент кода:** Пункт «Агент кода» в левой навигации. Для нативных инструментов нужна совместимая модель. «Исследовать код» допускает только чтение; «Предложить правки» создаёт отдельный набор. Перед загрузкой пользователь просматривает изменения. Известные ограничения реального агента приведены в [KNOWN_ISSUES.md](KNOWN_ISSUES.md).

**Генератор документации:** «Документация → Создать документ» либо кнопка «Документировать» в редакторе BSL. Используется существующее подключение модели; отдельные зависимости не нужны. Поставляемые скилл и шаблон находятся в `athena/skills/documentation-generator/`. Пошаговая работа и ограничения описаны в [руководстве пользователя](USER_GUIDE.md).

## Данные, резервная копия и обновление

`.athena` содержит выгрузки `exports`, базу знаний `knowledge.sqlite3`, справку `reference.sqlite3`, модели, GPU-окружение, наборы `change-sets`, журналы задач `agent-runs`, документы `documents` и локальные настройки. Она игнорируется Git. Браузерные черновики редактора хранятся в `localStorage` и не входят в копию `.athena`.

Перед переносом или обновлением завершите операции выгрузки/загрузки, остановите агента, генерацию документации и индексацию, закройте IDE-сервис и отдельный сервис справки. Копируйте `.athena` целиком, включая SQLite WAL/SHM, если они остались. Скопируйте исходную информационную базу штатными средствами 1С, если планируется загрузка изменений. Не удаляйте `.athena`, чтобы просто обновить исходники.

Затем в остановленном клоне:

```powershell
git pull --ff-only
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe -m athena.server
```

Обычная остановка IDE — Ctrl+C в её терминале. Сервис справки независим: закрытие IDE не завершает его. Если требуется явное управление справкой, запустите `python -m athena.reference_server --port 8767` в отдельном терминале; перед запуском убедитесь, что прежний процесс не занимает порт.

## Диагностика

| Симптом | Проверка |
| --- | --- |
| Порт занят / открывается старая версия | Проверьте адрес и процессы, оставьте один нужный экземпляр. Можно указать `--port 8766`. Обновите браузер Ctrl+F5. |
| Зависимости не найдены | Запускайте Python из `.venv`; повторите установку `requirements.txt` этим же интерпретатором. |
| Код не помещается в контекст документации | Выделите меньший фрагмент или увеличьте лимит контекста в настройках AI. Для большого проекта создавайте документы по модулям. |
| Ошибка 401 модели | Введите ключ в настройки текущего процесса. Проверьте адрес и модель. |
| CUDA недоступна | Проверьте GPU/драйвер и журнал `.athena/gpu-install.log`; продолжите на CPU. |
| Импорт/индексация долго работают | Проверьте этап и прогресс; большие модули требуют времени. Не запускайте параллельный импорт той же базы. |
| Набор агента содержит 0 изменений | Прочитайте фазу и журнал задачи; наличие набора не означает, что агент выполнил правку. См. известные проблемы. |
| Мало места на диске | Проверьте `exports`, SQLite, модели и GPU-окружение. Сначала сделайте копию и определите активную выгрузку; не удаляйте файлы работающего SQLite. |

Это локальный прототип, а не многопользовательский сервер. Не выставляйте порты в интернет и не меняйте привязку `127.0.0.1` без отдельной работы над аутентификацией, разграничением доступа и эксплуатацией.
