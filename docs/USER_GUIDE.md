# Руководство пользователя Athena

## Аккаунты и роли

Первый вход: **admin / admin**. После входа кнопка с логином в боковом меню открывает аккаунт; там же находится выход. Администратор создаёт пользователей, задаёт пароль и выбирает роль. Пароли хранятся в виде PBKDF2-хешей, сессия действует до 12 часов.

| Роль | Возможности |
|---|---|
| Программист | Общие функции IDE, свои запросы и наборы изменений |
| Главный программист | Всё выше, общий журнал AI, исправления ответов, отмена предложений других пользователей |
| Администратор | Всё выше, создание аккаунтов всех трёх ролей |

В аккаунте главного программиста/администратора **Запросы к моделям** показывает реальные запросы и ответы всех пользователей, начиная с установки этой функции, включая шаги агента, автодополнение и генерацию документации. Запросы к справочнику моделей без генерации не записываются. Ключи подключения и заголовки авторизации в журнал не попадают. Старые запросы, для которых приложение не сохраняло транспорт, восстановить невозможно.

Выберите запрос, введите правильный ответ и объяснение ошибки, нажмите **Сохранить исправление и индексировать**. Исправление сохраняется отдельно от исходного ответа и автоматически поступает в эмбеддинги исходного проекта. Такие материалы агент находит как проверенные примеры; при необходимости назначьте им роль обязательных правил в базе знаний.

В **Изменениях пользователей** можно отменить локальный набор: он архивируется, а его пакет блокируется для загрузки. Для уже загруженных изменений BSL создаётся **обратный набор**, если после загрузки код не менялся. Проверьте его в «Правках» и отдельно подтвердите импорт. Автоматическое удаление созданных объектов из 1С и отмена старых наборов без сохранённого исходного текста не поддерживаются; для них нужно ручное восстановление. Старые наборы без автора доступны для управления старшим ролям. Черновики браузера теперь разделены по аккаунтам; старые черновики остаются в хранилище браузера без автоматического присвоения авторства.

Текущий проект, настройки подключений и очередь AI общие для процесса Athena. Аккаунты не создают отдельные экземпляры IDE или информационной базы.

## Git-проекты

Откройте основную выгрузку 1С, дождитесь индексации и перейдите в **Документация → Git-проекты**. Укажите HTTPS/SSH-адрес и нажмите **Скачать и подключить**. Допустим и абсолютный путь к локальному Git-репозиторию: Athena создаёт отдельный клон. К одному проекту можно подключить до 20 источников: стандарты, документацию, связанные конфигурации. Подключения сохраняются отдельно для каждого основного проекта.

Git должен быть в PATH. Для закрытых репозиториев заранее настройте Git Credential Manager или SSH; токен и пароль в URL запрещены. Имя и email автора коммитов задаются обычными настройками Git (`git config --global user.name` и `git config --global user.email`). Интерактивного ввода учётных данных в Athena нет.

Флажок **Учитывать в ответах** включает источник в поиск, первоначальный контекст агента, поиск контекста AI и генерацию документации. Выдержки содержат репозиторий, путь, строки и SHA-256 файла. Это справочные данные, не обязательные правила проекта. Агент может искать только по Git через `search scope=git`; `scope=documents` и `scope=all` также включают Git. При обновлении проиндексированных источников текущая задача агента останавливается, чтобы не продолжать по устаревшим материалам.

Поддерживаются MD/TXT/RST, BSL/OS/XML, распространённые текстовые исходники, JSON/YAML/SQL, PDF с текстовым слоем и DOCX. Поиск Git работает по словам, без эмбеддингов. Лимиты на источник: 2000 файлов, 20 МБ суммарно, 2 МБ и 250000 символов на файл; пропуски видны в карточке. Подмодули, ссылки, `.git`, `.athena`, `.env`, зависимости и явно названные credentials/secrets не читаются. Это не заменяет проверку содержимого репозитория.

**Получить изменения** выполняет fetch и обновляет ветку только через fast-forward. Локальные правки или расхождение веток останавливают обновление с объяснением; конфликты разрешаются во внешнем Git. Флажок **Обновлять из Git каждую минуту** включает этот цикл автоматически. Изменения локальных клонов проверяются каждую минуту даже без сетевого обновления; кнопка **Обновить локальный индекс** применяет их к поиску сразу. Индекс и клоны находятся в `.athena/git`, путь клона виден в карточке.

Для отправки изменений:

1. При необходимости создайте **Новую ветку**.
2. Используйте **Редактировать / создать файл** или внешний редактор. Для публикации текущей выгрузки нажмите **Копировать открытый проект** и задайте каталог назначения: XML/BSL копируются с заменой совпадающих путей. Удаления автоматически не переносятся. Копирование ограничено 20 МБ/2000 файлами и требует чистого клона.
3. Выберите файлы и нажмите **Просмотреть выбранные файлы и создать коммит**. Проверьте diff и укажите сообщение. Если файлы изменились после просмотра, повторите просмотр. Уже подготовленные во внешнем Git staged-изменения блокируют создание коммита в Athena.
4. Нажмите **Push в origin**. Коммиты текущей ветки отправляются в одноимённую ветку origin без force-push. При отказе сервера коммит остаётся локально. Удалённый репозиторий предварительно создаётся на Git-сервере; Athena умеет заполнять в том числе пустой репозиторий.

Предложения модели остаются в наборах изменений и автоматически в Git не записываются. Сначала проверьте и примените их в обычном процессе 1С, затем скопируйте актуальную выгрузку в клон и просмотрите diff. Отключение источника убирает его из контекста, сохраняя клон и неотправленные коммиты на диске.

## Открыть проект

Запустите Athena по [инструкции развёртывания](DEPLOYMENT.md), откройте `http://127.0.0.1:8765/` и пройдите мастер настройки. Кнопкой «Открыть» выберите каталог файловой выгрузки, содержащий `Configuration.xml`. Для знакомства подходит `examples/demo`.

Дождитесь завершения индексации. Проект выбирается в шапке; меню дополнительных действий содержит выгрузку из 1С, автообновление и настройки автодополнения. Для просмотра выгрузки установленная 1С не нужна; выгрузка и загрузка изменений требуют платформы и доступа к базе.

## Навигация и панели

- **Главная** — вопрос по текущей конфигурации, последние вопросы и состояние проекта.
- **Код** — дерево метаданных, свойства, структура, связи и XML/BSL-модули. Компактная строка поиска по конфигурации всегда видна сверху; отдельной кнопки поиска в навигации нет. «Правки» и «Свойства» доступны только в этом разделе.
- **Документация** — генератор, сохранённые документы, справка платформы и переход к структуре конфигурации.
- **История** — вопросы текущего проекта; выбор записи открывает сохранённый ответ. Если ответ больше недоступен, вопрос подставляется для ручного повторного запуска.
- **AI-помощник** — вопросы по коду, объектам и связям, без изменения исходников.
- **Агент кода** — исследование либо предложения изменений в отдельном наборе.

Для поиска введите запрос в верхней строке и нажмите **Enter** или значок лупы. Режимы: **Код + смысл**, **Имена и код**, **По смыслу**. Результаты открываются поверх редактора; выбор метода переводит к его коду. **Esc**, крестик выдачи или щелчок вне поиска скрывают результаты, оставляя строку доступной. **Ctrl+Shift+F** переводит фокус в поиск. Кнопка настроек справа раскрывает состояние смыслового индекса и параметры индексации.

Стрелка над навигацией сворачивает её до иконок; `Ctrl+\` переключает то же состояние. В «Коде» дерево сворачивается своей стрелкой и возвращается кнопкой «Объекты» в шапке. Состояния сохраняются в браузере независимо друг от друга. Сворачивание не закрывает модуль и не сбрасывает черновик редактора. Настройка уменьшения движения в системе отключает анимации.

## Подключить модель

В AI-помощнике откройте «Настройки → Настройки подключения». Выберите Ollama либо OpenAI-совместимый API, укажите адрес сервера, модель и при необходимости API-ключ. Проверьте подключение. Для внешнего сервера отдельно разрешите передачу кода в настройках этого подключения.

Настройки адреса и модели сохраняются, API-ключ — только в памяти процесса. После перезапуска сервиса ключ нужно ввести заново. Наличие ключа и успешный HTTP-запрос не подтверждают качество модели. Для агента нужна поддержка нативных инструментов; генератор документации использует обычную генерацию текста.

## Задать вопрос и найти код

В «AI-помощнике» введите, например, «Какие есть документы?» или «Сколько собственных реквизитов в каждом справочнике?». Общие перечни и структурные счётчики берутся из XML-метаданных. Стандартные реквизиты, собственные реквизиты и реквизиты табличных частей не следует смешивать.

Свободные вопросы, например об обработчике или связях методов, исследуются инструментами агента в режиме чтения. Откройте «Что проверил помощник», чтобы посмотреть фактические вызовы и ошибки. Ссылки на источники позволяют перейти к коду. «Найти контекст» подбирает источники без генерации ответа.

Для самостоятельного просмотра перейдите в «Код», найдите объект в дереве, откройте вкладку «Код» и выберите BSL-модуль. XML описывает структуру объекта; обработчики и функции находятся в BSL. Лексический поиск доступен без эмбеддингов; смысловой индекс включается отдельно.

## Выбрать режим агента

**Исследовать код** — чтение метаданных, модулей, методов и связей, без создания предложений изменений.

**Предложить правки** — собственный набор задачи: изменения BSL и создание справочников/документов, локальная проверка и подготовка пакета. Агент не меняет структуру существующих объектов и не загружает изменения в базу самостоятельно.

После выполнения нажмите «Просмотреть предложения в Правках» и проверьте фактическую разницу, число изменений и результаты разбора. При достижении лимита читайте фазу и журнал: наличие набора ещё не означает наличие правки. Для загрузки используйте тестовую базу и существующий процесс просмотра/подтверждения; обновление конфигурации базы данных выполняется в 1С пользователем.

Повторные чтения возвращаются из памяти, а отсутствие новых фактов приводит к запросу итогового ответа. Остановка запрещает дальнейшие действия, но уже отправленный запрос к модели может ожидать ответа или тайм-аута. До этого общий слот AI остаётся занят.

## Загрузить знания и правила для агента

1. Откройте проект и перейдите в **Документация → Материалы проекта → База знаний агента**.
2. Выберите MD, TXT, PDF с текстовым слоем или DOCX, размером до 2 МБ. Из DOCX читается основной текст; картинки не распознаются. Для сканированного PDF сначала нужен OCR.
3. Если файл содержит инструкции, которым агент должен следовать, включите **Обязательные правила проекта**. Все включённые правила вместе ограничены 12 000 символов: они передаются целиком на каждом шаге, включая шаги после сокращения истории. Большие руководства загружайте как справочные документы.
4. Нажмите **Загрузить и индексировать**. Эмбеддинги автоматически считаются локально в фоне с настройками CPU/GPU рабочего места. Карточка показывает готовность и число фрагментов; при ошибке доступна кнопка **Повторить**. Пока модель недоступна, агент может искать по словам, а правила уже действуют.
5. Нажмите **Прочитать**, чтобы проверить извлечённый текст. Документ можно отключить или изменить его роль. Отключённые документы исключаются из поиска и правил.

Агент автоматически ищет подходящие выдержки по задаче, а затем может использовать инструмент `search` с `scope=documents`. Ссылки содержат имя файла, хеш и строки извлечённого текста. Обязательные правила закреплены отдельно от поиска; превышение контекста останавливает задачу, а не обрезает правила. Изменение состава документов или правил во время задачи также останавливает её: запустите заново для применения актуальных инструкций.

Материалы привязаны к проекту и сохраняются в `.athena/document_knowledge.sqlite3`. Хранятся извлечённый текст и производные векторы; оригинальные файлы не копируются. Индексация не отправляет текст внешнему сервису. При использовании внешней модели правила и найденные фрагменты передаются ей с тем же явным разрешением, что и код. Закрепление правил обеспечивает их присутствие в запросах, но не гарантирует безошибочного исполнения моделью: предложения кода по-прежнему требуют проверки.

## Создать документацию по конфигурации

1. Откройте проект, дождитесь индексации и настройте модель.
2. Перейдите в **Документация → Создать документ**.
3. Укажите название и тип: «Архитектура», «Возможности», «Описание кода», «Разработка», «Развёртывание» или «Известные проблемы».
4. Оставьте область «Текущая конфигурация». При необходимости уточните аудиторию и задачу в поле «Что описать».
5. Нажмите **Создать документацию** и дождитесь результата. Можно остановить генерацию.
6. Прочитайте предупреждения и раскройте **Использованные исходники**. При ограниченном контексте обзор проекта может быть неполным.
7. Проверьте текст. На вкладке **Markdown** внесите исправления и нажмите **Сохранить**. Кнопки **Скачать .md** и **Скачать PDF** выгружают текущий текст, включая несохранённые исправления, с данными об источниках и ограничениях. Скачивание само по себе не сохраняет исправления в библиотеку.

PDF создаётся локально: кириллица и шрифты встроены, заголовки, списки, таблицы и блоки кода оформляются с переносами страниц и нумерацией. Внешние изображения не загружаются; вместо них выводится описание. Для экспорта готового документа подключение к модели не требуется.

Документ автоматически сохраняется как черновик в библиотеке текущего проекта. После повторного открытия приложения он доступен в разделе «Документация». Файлы хранятся в `.athena/documents`; они не меняют исходники конфигурации и не отправляются в Git автоматически.

## Создать документацию по выделенному коду

1. В **Коде** откройте нужный объект, его вкладку **Код** и BSL-модуль.
2. В редакторе выделите нужный метод или фрагмент. Если включён просмотр исходника, переключитесь в режим редактирования BSL.
3. Нажмите **Документировать**. Откроется окно с областью **Выделенный код**, путём файла, строками и предпросмотром фрагмента. Без выделения выбирается **Открытый модуль**.
4. Проверьте область и задайте, что нужно описать, например: «Объясни назначение, параметры, обращения к регистрам и ограничения метода».
5. Создайте документ, проверьте и сохраните результат, как описано выше.

Несохранённые правки редактора могут быть источником документации и явно помечаются как черновик. Создание документа их не записывает в BSL. Если код изменился на диске после открытия окна, откройте актуальный модуль и запустите генерацию заново.

Скилл `Documentation Generator` и оригинальный `DOCUMENT_TEMPLATE.md` уже поставляются рядом в `athena/skills/documentation-generator/`. Генератор передаёт модели текст скилла и структуру разделов шаблона; отдельной установки в Codex или другую LLM-систему не требуется.

## Ограничения документации и диагностика

| Ситуация | Что делать |
| --- | --- |
| Требуется ключ / ошибка 401 | Введите API-ключ в настройках подключения текущего процесса. |
| Внешняя передача кода запрещена | Используйте локальную модель либо разрешите передачу выбранному серверу, если это допустимо для проекта. |
| Код не помещается в контекст | Выделите меньший фрагмент или увеличьте лимит контекста AI. Фрагмент и отдельный модуль должны помещаться целиком. |
| В контекст вошла часть проекта | Проверяйте список источников; для подробного описания создавайте отдельные документы по модулям. |
| Проект или модуль изменился | Обновите модуль, откройте окно заново и повторите запрос. |
| Достигнут лимит длины | Документ отмечен неполным; сузьте задачу и создайте новый документ. |
| Генерация прервана перезапуском | Создайте документ заново; незавершённый запрос автоматически не возобновляется. |

Модель получает статические исходники. Генератор не запускает тесты или 1С и не выполняет независимую смысловую проверку каждого утверждения. Ссылки, примеры, ограничения и бизнес-логику проверяет разработчик. Проверки интерфейса с тестовой моделью не подтверждают точность настоящей модели.

Карточки подключения Git-проекта и загрузки файлов документации пока обозначены «Скоро» и отключены. Источником генератора служит открытая файловая выгрузка, а не содержимое этих карточек.
