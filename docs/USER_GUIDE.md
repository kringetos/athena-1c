# Руководство пользователя Athena

## Открыть проект

Запустите Athena по [инструкции развёртывания](DEPLOYMENT.md), откройте `http://127.0.0.1:8765/` и пройдите мастер настройки. Кнопкой «Открыть» выберите каталог файловой выгрузки, содержащий `Configuration.xml`. Для знакомства подходит `examples/demo`.

Дождитесь завершения индексации. Проект выбирается в шапке; меню дополнительных действий содержит выгрузку из 1С, автообновление и настройки автодополнения. Для просмотра выгрузки установленная 1С не нужна; выгрузка и загрузка изменений требуют платформы и доступа к базе.

## Навигация и панели

- **Главная** — вопрос по текущей конфигурации, последние вопросы и состояние проекта.
- **Код** — дерево метаданных, свойства, структура, связи и XML/BSL-модули. Поиск по коду, «Правки» и «Свойства» появляются в навигации только в этом разделе.
- **Документация** — генератор, сохранённые документы, справка платформы и переход к структуре конфигурации.
- **История** — вопросы текущего проекта; выбор записи открывает сохранённый ответ. Если ответ больше недоступен, вопрос подставляется для ручного повторного запуска.
- **AI-помощник** — вопросы по коду, объектам и связям, без изменения исходников.
- **Агент кода** — исследование либо предложения изменений в отдельном наборе.

Стрелка над навигацией сворачивает её до иконок; `Ctrl+\` переключает то же состояние. В «Коде» дерево сворачивается своей стрелкой и возвращается кнопкой «Объекты» в шапке. Состояния сохраняются в браузере независимо друг от друга. Сворачивание не закрывает модуль и не сбрасывает черновик редактора. Настройка уменьшения движения в системе отключает анимации.

## Подключить модель

В AI-помощнике откройте «Настройки → Настройки подключения». Выберите Ollama либо OpenAI-совместимый API, укажите адрес сервера, модель и при необходимости API-ключ. Проверьте подключение. Для внешнего сервера отдельно разрешите передачу кода в настройках этого подключения.

Настройки адреса и модели сохраняются, API-ключ — только в памяти процесса. После перезапуска сервиса ключ нужно ввести заново. Наличие ключа и успешный HTTP-запрос не подтверждают качество модели. Для агента нужна поддержка нативных инструментов; генератор документации использует обычную генерацию текста.

## Задать вопрос и найти код

В «AI-помощнике» введите, например, «Какие есть документы?» или «Сколько собственных реквизитов в каждом справочнике?». Общие перечни и структурные счётчики берутся из XML-метаданных. Стандартные реквизиты, собственные реквизиты и реквизиты табличных частей не следует смешивать.

Свободные вопросы, например об обработчике или связях методов, исследуются инструментами агента в режиме чтения. Откройте «Что проверил помощник», чтобы посмотреть фактические вызовы и ошибки. Ссылки на источники позволяют перейти к коду. «Найти контекст» подбирает источники без генерации ответа.

Для самостоятельного просмотра перейдите в «Код», найдите объект в дереве, откройте вкладку «Код» и выберите BSL-модуль. XML описывает структуру объекта; обработчики и функции находятся в BSL. Лексический поиск доступен без эмбеддингов; смысловой индекс включается отдельно.

## Выбрать режим агента

**Исследовать код** — чтение метаданных, модулей, методов и связей, без создания предложений изменений.

**Предложить правки** — собственный набор задачи: изменения BSL и создание справочников/документов, локальная проверка и подготовка пакета. Агент не меняет структуру существующих объектов и не загружает изменения в базу самостоятельно.

После выполнения нажмите «Просмотреть предложения в Правках» и проверьте фактическую разницу, число изменений и результаты разбора. При достижении лимита читайте фазу и журнал: наличие набора ещё не означает наличие правки. Для загрузки используйте тестовую базу и существующий процесс просмотра/подтверждения; обновление конфигурации базы данных выполняется в 1С пользователем.

Повторные чтения возвращаются из памяти, а отсутствие новых фактов приводит к запросу итогового ответа. Остановка запрещает дальнейшие действия, но уже отправленный запрос к модели может ожидать ответа или тайм-аута. До этого общий слот AI остаётся занят.

## Создать документацию по конфигурации

1. Откройте проект, дождитесь индексации и настройте модель.
2. Перейдите в **Документация → Создать документ**.
3. Укажите название и тип: «Архитектура», «Возможности», «Описание кода», «Разработка», «Развёртывание» или «Известные проблемы».
4. Оставьте область «Текущая конфигурация». При необходимости уточните аудиторию и задачу в поле «Что описать».
5. Нажмите **Создать документацию** и дождитесь результата. Можно остановить генерацию.
6. Прочитайте предупреждения и раскройте **Использованные исходники**. При ограниченном контексте обзор проекта может быть неполным.
7. Проверьте текст. На вкладке **Markdown** внесите исправления и нажмите **Сохранить**. Кнопка **Скачать .md** выгружает текущий текст с данными о генерации, источниках и ограничениях.

Документ автоматически сохраняется как черновик в библиотеке текущего проекта. После повторного открытия приложения он доступен в разделе «Документация». Файлы хранятся в `.athena/documents`; они не меняют исходники конфигурации и не отправляются в Git автоматически.

## Создать документацию по выделенному коду

1. В **Коде** откройте нужный объект, его вкладку **Код** и BSL-модуль.
2. В редакторе выделите нужный метод или фрагмент. Если включён просмотр исходника, переключитесь в режим редактирования BSL.
3. Нажмите **Документировать**. Откроется окно с областью **Выделенный код**, путём файла, строками и предпросмотром фрагмента. Без выделения выбирается **Открытый модуль**.
4. Проверьте область и задайте, что нужно описать, например: «Объясни назначение, параметры, обращения к регистрам и ограничения метода».
5. Создайте документ, проверьте и сохраните результат, как описано выше.

Несохранённые правки редактора могут быть источником документации и явно помечаются как черновик. Создание документа их не записывает в BSL. Если код изменился на диске после открытия окна, откройте актуальный модуль и запустите генерацию заново.

Скилл `Documentation Generator` и оригинальный `DOCUMENT_TEMPLATE.md` уже поставляются рядом в `athena/skills/documentation-generator/`. Генератор передаёт модели текст скилла и структуру разделов шаблона; отдельной установки в Codex или другую LLM-систему не требуется.

## Ограничения документации и диагностика

| Ситуация | Что делать |
| --- | --- |
| Требуется ключ / ошибка 401 | Введите API-ключ в настройках подключения текущего процесса. |
| Внешняя передача кода запрещена | Используйте локальную модель либо разрешите передачу выбранному серверу, если это допустимо для проекта. |
| Код не помещается в контекст | Выделите меньший фрагмент или увеличьте лимит контекста AI. Фрагмент и отдельный модуль должны помещаться целиком. |
| В контекст вошла часть проекта | Проверяйте список источников; для подробного описания создавайте отдельные документы по модулям. |
| Проект или модуль изменился | Обновите модуль, откройте окно заново и повторите запрос. |
| Достигнут лимит длины | Документ отмечен неполным; сузьте задачу и создайте новый документ. |
| Генерация прервана перезапуском | Создайте документ заново; незавершённый запрос автоматически не возобновляется. |

Модель получает статические исходники. Генератор не запускает тесты или 1С и не выполняет независимую смысловую проверку каждого утверждения. Ссылки, примеры, ограничения и бизнес-логику проверяет разработчик. Проверки интерфейса с тестовой моделью не подтверждают точность настоящей модели.

Карточки подключения Git-проекта и загрузки файлов документации пока обозначены «Скоро» и отключены. Источником генератора служит открытая файловая выгрузка, а не содержимое этих карточек.
