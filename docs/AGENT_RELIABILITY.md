# Надёжность исследования кода

Изменения от 16.10.2026 относятся к механике Athena. Они не гарантируют качество рассуждений конкретной модели.

## Что изменено

| Область | Поведение |
| --- | --- |
| Поиск агента | `scope=code/all` подключён к существующему гибридному поиску. `exact=true` ищет точное имя без эмбеддингов. Ответ содержит `requested_mode`, фактический `mode` и предупреждение при переходе к словам. |
| Чтение | Модуль, метод, документ и справка сообщают реально переданные строки. `next_line/next_column` передаются как `start_line/start_column`; длинные строки дочитываются без пропусков. `get_symbol` предлагает продолжение через `read_module`. Ограничение транспорта повторно корректирует диапазон. |
| Память | Пути, хеши, диапазоны, частичность и отдельные фрагменты начала, середины и конца сохраняются независимо от истории. Удаление старых групп не разрывает пары вызов/результат. Уменьшение памяти не изменяет исходные наблюдения. Память подключается при вытеснении истории и финализации, чтобы не дублировать недавний код. |
| Покрытие | Учитываются фактически переданные кандидаты, прочитанные диапазоны, продолжения и непрочитанные кандидаты. Частично прочитанный метод не считается полностью прочитанным. Это покрытие найденных источников, а не доказательство полноты ответа на произвольный вопрос. |
| Повторы | Эквивалентные запросы с явными и неявными значениями по умолчанию используют кеш. После повторов модель получает направление к чтению методов, документов и связей. |
| Остановка | Два шага без новых данных больше не выключают инструменты. Ошибки аргументов допускают исправление в общем бюджете; реальные сбои имеют отдельный код `tool_failure` и отдельный последовательный счётчик. Финализация по лимиту отличается от обычного завершения и показывает причину. |
| Контекст | Учитываются инструкции, схемы, правила и справочные документы, память и история. Пустая справочная подборка не занимает историю. Необязательные формулы ограничены доступным местом. Бюджет ответа соблюдает `max_tokens`, включая повтор после усечения. |
| RAG | Поиск документов сообщает состояние индекса, причины исключения (отключение, порог, лимит) и отдельные режимы документов/Git. Найденные документы и снимки Git можно дочитать через `read_document` с проверкой проекта и включения источника. |
| Формулы | Автоматическая подборка даёт исходные доказательства и ID методов, сохраняется в учёте кандидатов и не отключает инструменты проверки окружающего кода. |
| Диагностика | В журнале есть исход вызова, безопасные параметры, хеш запроса, источники, фактические диапазоны, обрезка и объём удалённой истории. Полный запрос поиска и содержимое кода не добавляются в новую диагностическую трассу. Ключи подключения и пароли не включаются в неё. |

## Проверки

Итог полного запуска: 233 теста, 232 пройдены, 1 пропущен условием окружения; ошибок нет. Дополнительно прошли `node --check web/code-agent.js` и `git diff --check`.

`tests/test_agent_reliability.py` воспроизводит большой модуль с длинной строкой, чтение большого метода, сохранение тела и конца метода при сокращении истории, точный и гибридный поиск, лексический fallback, дочитывание документа и изоляцию проектов, чтение/запись регистра, обработчик формы, исправление трёх ошибочных вызовов и отличие сбоя ввода-вывода от ошибки аргументов. Существующие проверки памяти, редактирования, RAG, протоколов и отмены сохраняются.

При проверке интерфейса на отдельном временном пространстве подтверждено отображение режима поиска, покрытия, диапазонов, бюджета и причин завершения. Этот запуск использовал заглушку модели и учебный проект.

## Отдельное сравнение настоящих моделей

```powershell
python -m athena.agent_eval --models qwen3.5:9b qwythos-9b-q4:latest --max-seconds 90
```

Стенд создаёт временный учебный проект с синтетическими методами регистров. Каждая модель получает одинаковые задачи, инструменты, лексический индекс и бюджеты. Рабочие проекты и настройки пользователя не меняются. Передача предусмотрена только локальному Ollama. По умолчанию отчёт записывается в игнорируемый `.athena/evaluations/agent-models.json`; `--cases amount registers form` позволяет выбирать сценарии.

Метрики показывают названные методы, маркеры ответа, наличие этих маркеров в переданных диапазонах кода и ссылки на пути/строки. Само имя найденного метода без переданного кода не считается подтверждением. Эти проверки не являются семантической оценкой: точность цитат и объяснения нужно просматривать отдельно. Ошибка транспорта не считается оценённым ответом (`evaluated=false`).

Фактический запуск 16.10.2026: обе локальные модели на всех трёх задачах завершились HTTP 500 до первого вызова инструмента. Дополнительная минимальная проверка выявила `missing_llama_server_binary`: установленный Ollama не находит `llama-server.exe`. Это блокирует сравнение качества моделей. Стенд готов к повторному запуску после восстановления локального сервера; отсутствие результатов нельзя трактовать как низкое качество модели.

## Ограничения

Бюджет входа измеряется символами сериализованного контекста, выхода — токенами. Для Ollama размер нативного окна рассчитывается с приблизительным соотношением символов к токенам; точный токенизатор каждой модели не подключён. Реальный расход показывается из ответа провайдера. Большое нативное окно может требовать больше памяти.

При невозможности уместить структурированный ответ инструментов возвращается явный `not_delivered` и указание уменьшить страницу вместо оборванного JSON. Непрочитанное содержимое не добавляется в память как полученное доказательство. Компактная память ограничена; число исключённых наблюдений сообщается явно, исходные ответы можно запросить из кеша. Автоматического доказательства полноты бизнес-анализа пока нет.
