# Athena · IDE для 1С

Первый фундамент проекта: локальный просмотр иерархической файловой выгрузки из Конфигуратора 1С. Можно выбрать каталог, исследовать дерево метаданных, свойства и вложенные объекты, читать XML и BSL, искать объекты по имени и переходить к процедурам в модуле.

## Рабочее место IDE

Дерево слева сохраняется при открытии графа и редактора. Категории располагаются в привычном для 1С порядке; открытые объекты имеют отдельные закрываемые вкладки. Внутри объекта доступны свойства, структура, граф метаданных и код. Модули BSL сразу открываются для редактирования, XML — для просмотра. Между модулями можно переключаться кнопками над редактором или списком файлов.

BSL подсвечивается и при просмотре, и при вводе: ключевые слова, строки, числа, комментарии и вызовы функций. Редактор показывает номера строк, текущую строку и положение курсора. Кнопки «А−» / «А＋» меняют размер шрифта; настройка сохраняется в браузере. Подсветка не изменяет текст модуля и работает локально без внешних библиотек.

«＋» у категории справочников или документов открывает создание объекта во вкладке центральной области. Черновик можно оставить открытым и вернуться к нему после просмотра другого объекта. Панель «Правки» перечисляет изменённые модули текущего проекта и позволяет открыть их для проверки и подготовки загрузки. Ctrl+S сохраняет локальный черновик, отправка в 1С остаётся отдельным действием. Справа доступны свойства выбранного объекта; в узком окне они открываются кнопкой «Свойства» на боковой панели.

## Локальная база знаний для RAG

При открытии, выгрузке и автоматическом обновлении проекта Athena индексирует код в `.athena/knowledge.sqlite3`. SQLite работает в режиме WAL; версия схемы хранится в `user_version` (сейчас 2, миграция с версии 1 сохраняет данные). Основные сущности: проекты, снимки метаданных, модули, исходные тексты по хешу, процедуры и функции, фрагменты кода, связи вызовов, модели эмбеддингов, векторы и кеш векторов по тексту и версии модели.

Панель **Поиск** на левой полосе ищет методы по имени, комментариям и тексту через FTS5. Имена CamelCase дополнительно разбиваются на слова. Результат открывает модуль у объявления метода. Кнопка «Код и вызовы» показывает сохранённый текст, исходящие и входящие связи. При несовпадении хеша файла с индексом переход к строке блокируется; локальные черновики не смешиваются с сохранённой версией.

Новая версия публикуется транзакцией целиком; ошибка откатывает её, предыдущие версии остаются доступными в базе. Исходный текст и результаты разбора неизменённых модулей используются повторно. Фрагменты больших методов ограничены окнами в 120 строк с перекрытием в 20 строк. Код вне методов и неполностью разобранные участки тоже сохраняются для дальнейшего RAG. База не содержит паролей подключений и не отправляет данные внешним сервисам.

Индексатор использует синтаксическое дерево ANTLR с грамматикой BSL проекта 1c-syntax/bsl-parser v0.30.0. Поддерживаются процедуры, функции, асинхронные методы, директивы, аннотации, параметры с признаками «Знач» и значениями по умолчанию, составные обращения и вложенные вызовы. Ошибки синтаксиса сохраняются с путём, строкой и столбцом; незакрытые методы не публикуются как завершённые. Полные методы с ошибками доступны для поиска, но их вызовы не связываются с другими методами. Совпадения с экспортными методами общих модулей отмечаются как предположения; локальные переменные и параметры, затеняющие имя общего модуля, блокируют такую связь. Динамические вызовы, типы переменных и условия препроцессора не разрешаются. Это грамматический парсер, а не компилятор 1С. SDBL, индекс черновиков и AI-ответы поверх найденного контекста — следующие этапы. Источник, лицензии и команда воспроизводимой генерации находятся в `athena/bsl_grammar/PROVENANCE.md`.

Кнопка **Включить смысловой поиск** подключает локальную CPU-модель multilingual-e5-small. ONNX-веса (~118 МБ) и токенизатор (~17 МБ) загружаются с Hugging Face в `.athena/models`; закреплена ревизия `761b726dd34fb83930e26aab4e9ac3899aa1fa78` репозитория [Xenova/multilingual-e5-small](https://huggingface.co/Xenova/multilingual-e5-small). Исходный код и запросы не отправляются: обработка выполняется локально. Готовая модель загружается из кеша без сети. Настройка включения сохраняется в `.athena/semantic.json`; векторный индекс обновляется в фоне после смены или обновления проекта. Неизменённые входные тексты повторно используют векторы, в том числе между снимками.

В режиме **Гибридный** результаты FTS5 и косинусного поиска объединяются через Reciprocal Rank Fusion (вес FTS5 — 2, смыслового — 1, k=60); точное имя метода закрепляется первым. Запрос несуществующего имени вида CamelCase не подменяется похожими методами. Доступны отдельные режимы **Имена и код** и **По смыслу**. Пока векторный индекс текущего снимка не готов или модель недоступна, гибридный режим выполняет обычный поиск и показывает причину. Смысловой режим требует готового индекса.

Векторы нормализованы, хранятся как float32 little-endian и проверяются на размерность, конечность и ненулевую норму. Версия модели включает ревизию весов и рецепт подготовки текста. Вход содержит комментарий, разделённое на слова имя метода, объект и код фрагмента; длинный текст обрабатывается окнами до 512 токенов с перекрытием 64, их векторы усредняются. Готовый индекс публикуется одной транзакцией после успешного расчёта всех векторов. В смысловой поиск входят фрагменты завершённых методов; сохранённый код вне методов пока не ранжируется. Используется точный перебор векторов порциями по 512 строк SQLite, а не ANN; стоимость запроса растёт с размером проекта. Для очень больших конфигураций следующий шаг — отдельный индекс ближайших соседей. Порог косинусной близости 0.78 — начальная эвристика, а не вероятность правильного ответа; его нужно проверять на рабочих данных. Вызовы пока показываются как контекст и не входят в формулу ранжирования.

API: `GET /api/knowledge`, `GET /api/search-functions?q=...&mode=lexical|semantic|hybrid`, `GET /api/function?id=...`, `POST /api/embeddings` с `{"enabled":true|false}`. Все маршруты защищены токеном текущей сессии и ограничены текущим снимком проекта.

Проверка качества: `python -m athena.search_eval --output .athena/search-quality.json`. Она создаёт временную учебную конфигурацию и SQLite-базу, не изменяя открытый проект. Набор в `tests/fixtures/search/dataset.json` содержит 16 синтетических запросов: имена, префиксы, комментарии, текст кода, отрицательные запросы и два вопроса с перефразированием. На текущем лексическом поиске 12 из 14 положительных запросов находят ожидаемый метод в первых трёх результатах; оба отрицательных запроса дают пустой результат. Hit@3, средняя Recall@3 и MRR — 0.857. Лексический режим не находит два вопроса с перефразированием. Для сравнения запустите `python -m athena.search_eval --mode hybrid --output .athena/search-quality-hybrid.json`. На локальной E5 гибридный режим находит 13 из 14 положительных запросов в первых трёх результатах (Hit@3 и средняя Recall@3 — 0.929, MRR — 0.940), оба отрицательных запроса остаются пустыми. Один вопрос с перефразированием всё ещё не попадает в топ-3; результаты проверены на настоящей локальной модели, а не на тестовой подстановке. Режим `--mode semantic` позволяет оценить только векторный поиск. Эти результаты характеризуют только небольшой учебный набор; качество на рабочей конфигурации нужно оценивать отдельным размеченным набором. `--dataset` позволяет выбрать свой JSON; `--project` читает существующую файловую выгрузку вместо учебной.

## Граф метаданных

Вкладка **Граф метаданных** показывает состав выбранного объекта: родителя, группы типов, вложенные объекты и модули. Линии обозначают вхождение в состав. Списки открываются страницами по 8 элементов, поиск работает по всей конфигурации и сначала предлагает точные совпадения имени.

Щелчок по узлу открывает карточку с переходом к свойствам или коду; двойной щелчок раскрывает его состав. Фон и узлы можно перетаскивать, колесо и кнопки меняют масштаб, «Вписать» возвращает весь текущий граф в область просмотра. Дерево остаётся доступным рядом с графом. Граф работает локально без внешних библиотек.

## Запуск

В Windows откройте **Start.cmd**. Он запустит локальный сервер и откроет интерфейс в браузере: http://127.0.0.1:8765. Окно запуска должно оставаться открытым. Для остановки нажмите Ctrl+C в этом окне.

Нужен Python **3.10 или новее**; для системного диалога выбора папки нужен tkinter, который входит в обычную установку Python для Windows. Start.ps1 также обнаруживает Python, поставляемый с Codex на этом компьютере, и при необходимости устанавливает зависимости ANTLR и локальной модели из `requirements.txt`. Для первой установки нужен доступ к PyPI. После установки разбор работает локально; Java для запуска не требуется.

Ручной запуск из корня проекта:

```powershell
python -m pip install -r requirements.txt
python -m athena.server
# Другой порт, если 8765 занят:
python -m athena.server --port 8766
# Сразу открыть конкретную выгрузку:
python -m athena.server --project "C:\Проекты\Выгрузка"
```

## Открытие своей конфигурации

1. В Конфигураторе сохраните изменения и выполните **Конфигурация → Выгрузить конфигурацию в файлы**. Выберите иерархический формат выгрузки, если доступен выбор формата.
2. В Athena нажмите **Открыть проект → Обзор…** либо вставьте абсолютный путь.
3. Выберите папку, непосредственно содержащую **Configuration.xml**. Например, это может быть `src\cf`, а не корень Git-репозитория.
4. Выберите объект в дереве. В обзоре доступны свойства из XML и вложенные элементы. Вкладка **Код и XML** содержит исходники объекта и вложенных объектов.
5. После новой выгрузки нажмите **Обновить**: каталог будет заново прочитан, включая добавленные и удалённые файлы.

Откройте **Демо-проект** в диалоге, чтобы попробовать интерфейс без своей выгрузки. Это небольшой синтетический пример, а не готовая к загрузке в 1С конфигурация.

## Выгрузка кнопкой из базы 1С

Нажмите **Выгрузить из 1С**. Выберите базу из локального списка запуска 1С или укажите подключение вручную:

- Для файловой базы — каталог, содержащий `1Cv8.1CD`.
- Для серверной — адрес `сервер[:порт]/имя_базы`.
- Путь к **1cv8.exe** установленной платформы (толстый клиент). Обнаруженные стандартные установки предлагаются в поле; для другой папки используйте «Обзор…». `1cestart.exe` и тонкий клиент `1cv8c.exe` для выгрузки не подходят.
- Пользователь и пароль 1С, если нужны; либо аутентификация Windows. Нужны права на запуск Конфигуратора и выгрузку конфигурации, подходящая версия платформы и доступная лицензия.
- При необходимости — имя одного расширения. Без него выгружается основная конфигурация.

Нажмите **Выгрузить и открыть**. Athena запускает `1cv8.exe DESIGNER` с `/DumpConfigToFiles` в формате `Hierarchical`, показывает этап и время ожидания, проверяет код завершения, `/DumpResult` и наличие Configuration.xml, затем открывает выгрузку. При ошибке доступен журнал 1С. Выгрузку можно отменить; останавливается только процесс, запущенный Athena. После 60 минут ожидания он также останавливается.

Подключение сохраняется в `.athena/connections.json` **без пароля**. Пароль повторно используется только в текущем процессе Athena; после остановки приложения его потребуется ввести заново. При запуске пароль передаётся платформе параметром `/P`, поэтому может быть виден локальным средствам просмотра командных строк процессов; аутентификация Windows обходится без `/P`. Журнал маскирует переданный пароль перед отображением и сохранением окончательного результата.

После успешной выгрузки кнопка **Выгрузить снова** повторяет операцию для текущей базы. После перезапуска можно открыть последний результат из недавних проектов — Athena восстановит связь с подключением. Каждый запуск создаёт новую папку `.athena/exports/<подключение>/<запуск>/configuration`; ранее полученные выгрузки сохраняются. Старые снимки пока не очищаются автоматически.

Выгружается **сохранённая конфигурация**, а не несохранённый текст открытого редактора и не содержимое пользовательских таблиц. Athena не применяет изменения к конфигурации или конфигурации базы данных. Занятый Конфигуратор, блокировки, неверные учётные данные и отсутствие лицензии могут помешать отдельному пакетному запуску.

Механизм основан на [штатной пакетной выгрузке 1С](https://kb.1ci.com/1C_Enterprise_Platform/What___s_New/Functional_Highlights/Incremental_export_of_configurations_to_XML_files/) и [параметрах подключения](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Administrator_Guides/1C_Enterprise_8.3.24_Administrator_Guide/Appendix_7._The_parameters_of_the_command_line_to_launch_1C_Enterprise/7.3._General_startup_commands/7.3.1._Connection_parameters/?language=en).

## Что поддерживается

- Объекты `MetaDataObject` из отдельных XML-файлов, включая виды, неизвестные текущему словарю русских названий.
- Вложенные реквизиты, табличные части, измерения, ресурсы, значения перечислений, формы и команды из `ChildObjects`.
- Модули объекта, менеджера, набора записей, форм, команд, общих модулей и конфигурации; остальные BSL/OS-файлы тоже доступны.
- Сырые XML-свойства, синонимы, дерево и фильтр по имени/типу/синониму.
- Номера строк, базовая подсветка BSL, поиск по открытому файлу, копирование и переход к объявлениям процедур/функций.
- Предупреждения о повреждённых XML и объектах, перечисленных в Configuration.xml, для которых нет отдельного XML.
- Список последних каталогов в `.athena/recent.json`.

## Границы первой версии

Приложение читает XML/BSL из выбранной папки или получает их пакетной выгрузкой из базы. Файлы `.cf`, `.dt`, EDT `.mdo` и плоский формат выгрузки пока не поддерживаются. Расширение можно выгрузить и открыть отдельно; объединение основной конфигурации и расширений не реализовано.

Объекты без модуля показывают свои метаданные. Содержимое форм, макетов и прав доступно как XML, но визуального редактора этих элементов пока нет. Стандартные реквизиты, не представленные в выгрузке, из платформы не достраиваются. Переходы к процедурам и подсветка выполняются лёгким лексическим проходом; это не семантический анализ BSL.

Загрузка выполняется в фоне с отображением прогресса. Каталог хранится в памяти, исходники читаются по запросу. Граф показывает состав метаданных. Автообновление проверяет сохранённую конфигурацию, а при изменениях создаёт полный снимок; SQLite-индекс, граф вызовов и ИИ добавляются следующим этапом. Для очень больших модулей потребуется виртуализация строк просмотрщика.

Исходники не отправляются во внешние сервисы. Просмотр и локальные черновики не меняют исходную выгрузку; отдельная кнопка загрузки записывает выбранный BSL-модуль в конфигурацию 1С. Сервер слушает только `127.0.0.1`; API требует случайный токен текущего запуска. Это приложение для одного локального пользователя и одного открытого проекта.

## Структура

```text
athena/catalog.py   — разбор выгрузки, каталог объектов, связь с файлами
athena/exporter.py  — подключения, обнаружение баз и платформ, пакетная выгрузка
athena/editing.py   — подготовка изменений, резервная копия, выборочная загрузка BSL
athena/server.py    — локальное API, фоновые задания, выбор папки
web/               — интерфейс без сборки и внешних CDN
examples/demo/     — демонстрационная структура XML/BSL
tests/             — проверки загрузчика и API
```

Ядро отделено от HTTP-адаптера; при добавлении ИИ можно заменить адаптер на FastAPI, сохранив загрузчик и формат каталога.

Проверки:

```powershell
python -m unittest discover -s tests -v
```

## Автообновление при сохранении в Конфигураторе

Нажмите **Автообновление**, включите переключатель и выберите интервал (30 секунд — 5 минут). Нужен открытый снимок, связанный с подключением 1С, и файл `ConfigDumpInfo.xml`. После запуска Athena при необходимости введите пароль подключения в этом окне. Пароль остаётся только в памяти.

Athena в фоне запускает штатную проверку `/DumpConfigToFiles ... -getChanges -configDumpInfoForChanges ...` в отдельном временном каталоге. Для сравнения используется `ConfigDumpInfo.xml` открытого снимка; исходная выгрузка не является каталогом назначения. Если сохранённых изменений нет, новая выгрузка не создаётся. Если изменения есть, выполняется полная выгрузка в новый снимок и повторное чтение метаданных. Граф, свойства и открытый код обновляются с сохранением выбранного объекта, вкладки, файла и положения графа (если его состав не изменился). Удалённый объект заменяется конфигурацией. Несохранённый текст редактора 1С недоступен; обновление базы данных не требуется.

Опрос продолжает работать при закрытой вкладке, пока запущен сервер Athena. Проверки и ручные выгрузки не запускаются параллельно. При ошибке остаётся предыдущий проект; причина показана в настройках. Отключение останавливает текущую фоновую операцию 1С, если она ещё выполняется. После перезапуска автообновление выключено. На большой конфигурации полный экспорт и индексация могут занять несколько минут: интервал задаёт частоту проверки, а не гарантированный срок обновления.

Механизм проверки: [документация 1С](https://kb.1ci.com/1C_Enterprise_Platform/What___s_New/Functional_Highlights/Incremental_export_of_configurations_to_XML_files/).

## Редактирование BSL и загрузка модуля в 1С

Во вкладке **Код и XML** выберите BSL-файл и нажмите **Редактировать BSL**. Tab вставляет отступ; Ctrl+S сохраняет локальный черновик. При переключении между файлами и обновлении проекта черновики сохраняются в хранилище браузера. XML остаётся доступен для просмотра. Для отправки нужна выгрузка, связанная с подключением 1С.

**Подготовить загрузку** сохраняет исходный текст и изменённый модуль в `.athena/changes/<id>/`, показывает разницу и целевое подключение. Кнопка **Загрузить в 1С** запускает проверку сохранённой конфигурации относительно снимка через `-getChanges`, затем выборочную загрузку единственного BSL-файла через `/LoadConfigFromFiles ... -partial -files ... -Format Hierarchical`. Потребуется платформа с поддержкой этих параметров (для проекта используется 8.5). Права, поддержка конфигурации и блокировки хранилища проверяются платформой при загрузке.

Перед отправкой сохраните изменения в Конфигураторе и закройте редактор модуля: несохранённый текст редактора не участвует в проверке конфликтов. При обнаружении сохранённых изменений загрузка блокируется. Обновите выгрузку, просмотрите сравнение черновика с текущим исходником, примите новую основу и подготовьте загрузку повторно.

Загрузка изменяет сохранённую конфигурацию. Для выполнения новой логики обновите конфигурацию БД обычным способом в 1С; Athena эту операцию автоматически не запускает. Синтаксический контроль выполняйте в Конфигураторе. Пока идёт загрузка, фоновые проверки и другие операции 1С не запускаются параллельно. После загрузки Athena делает новый снимок и проверяет совпадение текста модуля с черновиком. Если загрузка прошла, а последующая проверка не завершилась, сообщение явно указывает на уже выполненную запись. Повторная отправка той же подготовленной операции запрещена.

Исходный BSL в `before.bsl` остаётся доступен для ручного восстановления. Черновики браузера не являются полноценной резервной копией; подготовка создаёт копии на диске. Подготовленные операции действуют только в текущем процессе Athena.

Выборочная загрузка описана в [руководстве разработчика 1С](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/?sphrase_id=1678862).


## Создание справочников и документов

Кнопка **Создать объект** открывает конструктор имени, синонима, реквизитов, табличных частей и двух BSL-модулей. Поддержаны строка (длина 0–4096), число (разрядность 1–38 и точность), булево, дата со временем и ссылки на существующие справочники/документы. Имена проверяются без учёта регистра, стандартные реквизиты не разрешается дублировать. Формы явно не создаются; используются автоматические формы платформы. Документ создаётся без проведения и движений по регистрам. Подсистемы и права настраиваются в Конфигураторе. Создание в расширениях пока не поддерживается.

Черновик конструктора сохраняется в браузере для текущего проекта. **Подготовить объект** создаёт отдельный пакет в `.athena/objects/<id>/`: XML объекта, модули, изменённый `Configuration.xml`, копии внешних свойств корневой конфигурации (в том числе настроек поддержки, если они присутствуют), исходный `Configuration.before.xml` и журнал операции. Исходная выгрузка остаётся неизменной. На локальном проекте без подключения пакет можно подготовить; кнопка отправки доступна для выгрузки, связанной с 1С. После перезапуска подготовьте пакет заново из сохранённого черновика.

**Загрузить в 1С…** открывает просмотр пакета и целевого подключения. После нажатия окончательной кнопки сначала проверяется отсутствие сохранённых изменений в базе, затем выполняется `/LoadConfigFromFiles ... -listFile ... -Format Hierarchical` с конкретным списком файлов: родительская конфигурация, новый объект и два модуля. Режим `-partial` для загрузки только внешних свойств здесь не применяется. Перечень существующих объектов в родительском XML сохраняется. Изменённый на диске пакет не принимается. Athena не запускает обновление конфигурации БД, не назначает права и не включает объект в подсистемы.

После загрузки создаётся новая выгрузка и проверяются UUID, имя, синонимы, реквизиты и типы, табличные части, код модулей, свойства родительской конфигурации и сохранность списка объектов. При успехе объект открывается в графе метаданных. При ошибке после начала записи операция не повторяется автоматически; состояние нужно проверить в Конфигураторе.

Проверено на отдельной файловой базе платформы **8.5.1.1522**: создание справочника и документа с реквизитами, табличными частями и кодом, затем создание документа через интерфейс со ссылкой на существующий справочник. Загрузка и обратная выгрузка выполнены настоящей платформой. Рабочая база пользователя в этих проверках не изменялась.

Порядок загрузки нового объекта вместе с родителем описан в [руководстве разработчика 1С, раздел 2.17.5.3.2](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/?sphrase_id=1678862).

### AI-помощник и подключение модели

Откройте **AI → Настройки подключения**. Поддерживаются два отдельных профиля:
- **Ollama**: базовый адрес `http://127.0.0.1:11434`, имя установленной модели.
- **OpenAI-совместимый API**: например, локальный LM Studio `http://127.0.0.1:1234/v1` или внешний API `https://api.openai.com/v1`. Укажите модель и при необходимости API-ключ.

«Проверить и получить модели» сохраняет профиль и запрашивает список моделей; успешная проверка списка не гарантирует успешную генерацию. Адрес, модель, ожидание ответа (10–300 секунд) и лимит контекста (4000–40000 символов) сохраняются в `.athena/ai.json`. API-ключ хранится только в памяти до остановки сервера и удаляется при смене адреса. Ключи не передаются браузеру обратно и не записываются в конфигурацию. Для внешнего подключения нужен HTTPS и включённое разрешение отправки вопроса и найденных фрагментов кода. HTTP поддерживается для loopback-адресов; перенаправления запросов отключены.

«Найти контекст» работает без генеративной модели и ничего ей не отправляет. «Ответить» ищет методы гибридным поиском, добавляет связанные методы и передаёт ограниченный контекст выбранной модели. Без указанной модели отображается только контекст. Источники `[S1]` открывают исходный модуль на соответствующей строке; содержимое контекста можно раскрыть в карточках. Используется сохранённый снимок проекта, при обновлении проекта результат сбрасывается. AI не изменяет исходники и конфигурацию.

Ответы модели требуют проверки: наличие ссылки подтверждает источник, но не правильность вывода. Отмена скрывает поздний ответ; транспортный запрос может продолжаться до ответа сервера или тайм-аута, и до его завершения новый запрос не запускается. Протоколы проверяются тестовым HTTP-сервером; для реальной генерации необходимо запустить/настроить собственную модель.

API с токеном Athena: GET `/api/ai/settings`, GET `/api/ai/job?id=…`; POST `/api/ai/settings`, `/api/ai/models`, `/api/ai/ask` (`question`, `context_only`), `/api/ai/cancel` (`id`).

При первичной индексации разбор BSL и запись снимка SQLite отображаются отдельными этапами с текущим модулем и живым временем. Лексер использует разреженный Unicode-кэш вместо повторного обхода ATN для кириллицы. Синтаксический разбор сначала выполняется в SLL с BailErrorStrategy; при ошибке повторяется в LL с исходной диагностикой. Грамматика и исходники конфигурации не меняются. Результаты завершённого разбора сохраняются по каждому модулю; снимок с метаданными, методами и связями публикуется одной транзакцией после полного завершения.

Смысловая индексация читает по 16 фрагментов, проецируя только комментарий, имя метода и объекта из SQLite. Каждый корректный пакет векторов и кэша сохраняется короткой транзакцией. После паузы или сбоя продолжение пропускает сохранённые фрагменты; публикация смыслового поиска происходит только после готовности полного снимка. При изменении кода используются векторы неизменившегося содержимого. «Приостановить» отключает фоновую индексацию и сохраняется между запусками. Вычисление текущего пакета может закончиться до остановки; сохранённые ранее пакеты остаются в базе.

Поиск по объектам и ключевым словам работает без E5. Он удаляет служебные слова вопроса, учитывает окончания русских слов, имена/синонимы объектов, ограничивает результаты соответствующими модулями и показывает релевантный участок кода. Встроено соответствие обычного выражения «счёт покупателю» документу `СчетНаОплату` (УНФ). Это словарный поиск, а не понимание произвольных вопросов нейросетью. Статистика неизменяемого снимка кэшируется; обновление прогресса не декодирует полный код всех методов.

Векторы, вычисленные старой реализацией и ещё не записанные в SQLite, восстановить после остановки нельзя. Пакетное сохранение действует для расчётов новой версии.


### Настройки локальной индексации
В панелях «Поиск» и «AI» доступна кнопка «Настройки индексации». CPU работает по умолчанию. «Комфортная работа» использует два потока (или один на одноядерной системе), пакеты до 8, бюджет 2048 токенов и паузу 100 мс. «Максимальная скорость» задаёт большие пакеты; расширенные настройки позволяют менять потоки, размер пакета, бюджет токенов, паузу и лимит памяти вычислителя GPU. Это не жёсткий лимит RAM или памяти всего процесса. Расчёт выполняется в фоновом потоке в обоих режимах; обычный поиск доступен независимо от готовности смыслового индекса.

Модель теперь получает настоящие пакеты окон, сгруппированные по длине. Порядок результатов и усреднение длинных фрагментов сохраняются. Готовые пакеты записываются в SQLite; при повторном запуске и изменениях используется сохранённый кэш. Настройки сохраняются отдельно от запуска индексации. Перед изменением настроек активный расчёт нужно приостановить и дождаться остановки.

GPU: только NVIDIA CUDA. В отдельном Python-окружении установите обычные requirements.txt, затем замените onnxruntime на onnxruntime-gpu совместимой версии. Инструкция по CUDA/cuDNN и драйверам: https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html . Не устанавливайте CPU и GPU пакеты ONNX одновременно. Запускайте Athena этим Python. В GPU режиме скачивается закреплённая FP32 модель, CPU использует Q8; их индексы разделены, при переключении требуется построение индекса соответствующей модели. Код остаётся локальным. Если CUDA недоступна, ошибка показывается явно; пользователь может выбрать CPU. Отдельные неподдерживаемые операторы могут исполняться на CPU. Работоспособность на конкретной GPU и ускорение нужно проверять на целевой машине.

Пакетная Q8-квантизация может немного менять векторы относительно прежнего расчёта по одному окну. Рецепт индекса обновлён: старые векторы сохраняются, но не смешиваются с новыми. Изменение количества потоков и размера пакета не удаляет прогресс нового индекса; точные значения Q8 могут зависеть от состава пакета. Проверка на коротком коде и длинном фрагменте с несколькими окнами дала косинусную близость более 0,99 между одиночным и пакетным расчётом; это не оценка качества поиска на всей конфигурации.

### Справка платформы для редактора и агента
«Справка 1С» в шапке IDE открывает локальный синтакс-помощник на `http://127.0.0.1:8767/`. Отдельный процесс автоматически запускается вместе с IDE; его также можно запустить командой `python -m athena.reference_server --platform "G:\1С8.5\8.5.1.1522\bin\1cv8.exe"`. Этот процесс не перезапускает IDE и не останавливает расчёт эмбеддингов.

Импорт читает `shcntx_ru.hbk`, `shlang_ru.hbk`, `shquery_ru.hbk` рядом с выбранным `1cv8.exe`, объединяет цепочки блоков контейнера и читает вложенный FileStorage ZIP в памяти. Страницы не распаковываются на диск, платформа не запускается. SQLite `.athena/reference.sqlite3` хранит версии отдельно, оригинальные пути статей, текст и найденные разделы (синтаксис, параметры, описание, доступность, примеры). Это первый этап: отдельная модель типов и параметров для автодополнения ещё не построена.

Поиск FTS5 работает без модели и GPU, ставит точное имя выше совпадений по префиксу и учитывает английские имена в заголовках. API отдельного сервиса: `GET /api/status`, `GET /api/search?q=...&source=...`, `GET /api/page?id=...`, `POST /api/import` с JSON `{"platform":"...1cv8.exe"}`. API требует локальный токен страницы. Импорт атомарный, повторный импорт неизменённых файлов использует готовый индекс; ошибка сохраняет предыдущую справку. HTML справки отображается как текст, без исполнения скриптов. Источники остаются локальными файлами установленной платформы пользователя.

### Наборы изменений
В разделе «Правки» можно создать именованный набор, добавить текущий модуль или все локальные черновики, а из окна создания объекта — добавить подготовленный справочник/документ. Флажки включают и исключают отдельные изменения; кнопка «Разница» показывает текущий исходник и подготовленную правку. «Проверить набор» проверяет версии файлов, существование объектов и BSL через ANTLR. «Подготовить общий пакет» создаёт один Configuration.xml с объединёнными ссылками на новые объекты и выбранными модулями. Исходная выгрузка не меняется.

Наборы и пакеты хранятся в `.athena/change-sets/<id>/`, восстанавливаются после перезапуска и разделены по подключению/проекту. Обновления проверяют ревизию набора, чтобы второе окно не перезаписало чужую работу. Пакет фиксирует исходные хеши и хеши подготовленных файлов; изменения после подготовки блокируют загрузку. Папка пакета содержит исходный Configuration.xml, резервные копии изменённых модулей и сохранённый просмотр разницы. Архивирование обратимо; восстановление черновика требует новой подготовки пакета. Архивирование не освобождает место на диске.

Загрузка выполняется через существующий диалог подтверждения и один список файлов 1С. Сначала проверяется наличие сохранённых изменений в конфигураторе, затем результат проверяется повторной выгрузкой: код, свойства новых объектов, список объектов и свойства конфигурации. Применённые наборы сохраняются как история. После запуска записи любой неясный результат помечается «Проверьте результат в 1С» и блокирует редактирование/повторную загрузку этого набора. Запуск одной команды не гарантирует атомарность импорта платформой; при ошибке нужна проверка конфигуратора. Автоматического обновления конфигурации БД нет. Реальную загрузку набора в пользовательскую базу при разработке функции не запускали.

API: `GET /api/change-sets` и `POST /api/change-sets` с действием `create/read/add/enable/validate/prepare/review/archive`, идентификатором и ревизией набора; подготовленный пакет передаётся существующему `/api/apply-change`. Требуется токен IDE. Лимит: 100 элементов и 25 МБ данных черновика. Поддерживаются правки существующих BSL-модулей и создание справочников/документов; изменение структуры существующих объектов — отдельное расширение инструментов.

### Автодополнение BSL
Кнопка «Автодополнение» в шапке IDE открывает настройки: включение, ручной/автоматический/комбинированный вызов, Ctrl+Пробел или Alt+/, источник (локальная справка и проект либо локальные подсказки + AI), версия справки, задержки и минимальная длина префикса. Настройки сохраняются в `.athena/completion.json`. По умолчанию работает локальный комбинированный режим, задержка 350 мс, префикс от двух символов. После точки длина префикса не ограничена.

Локальные подсказки включают ключевые слова, имена переменных/параметров/методов в доступном фрагменте черновика, объекты после `Справочники.` и `Документы.`, экспортные методы общих модулей, методы платформенных типов после простого присваивания `Новый`, менеджеры справочников и документов. `ЭтотОбъект.` использует реквизиты и табличные части владельца модуля. Это ограниченное определение типов, а не полная модель динамического BSL. В строках и комментариях подсказки отключены. Enter/Tab вставляет выбранное предложение, стрелки выбирают, Escape закрывает список. Смена текста, позиции или файла отбрасывает устаревший ответ. Вставка меняет только локальный черновик, не выгрузку и не базу 1С.

AI использует выбранный профиль AI-помощника (Ollama или OpenAI-совместимый API). Режим по умолчанию не вызывает модель. Для AI передаются до 6000 символов перед курсором, до 1500 после и несколько локальных подсказок; внешнему серверу код передаётся только при сохранённом разрешении `allow_remote_code`. Один запрос модели за раз, таймаут до 30 секунд, ответ до 256 токенов. Сбой модели оставляет локальные предложения. При автоматическом режиме отдельная задержка AI снижает количество запросов. Живое подключение модели требуется для реальной генерации; тесты проверяют транспорт и ограничения с подменённой моделью.

API основного сервиса: `GET/POST /api/completion/settings`, `POST /api/completion` с `before`, `after`, `file_id`, `neural`; требуется `X-Athena-Token`. Текущая проверенная версия IDE запущена на `http://127.0.0.1:8766/`; прежний процесс на 8765 сохранён, поскольку автоматическая проверка отклонила его перезапуск.

### Общий сервис знаний
Общий сервис знаний доступен в локальной странице справки: выбор проекта, поиск по всем источникам или отдельно по платформе, метаданным, коду, а также режим точного имени. Все результаты сохраняют происхождение, версию платформы либо снимок проекта и путь определения.

API для редактора и агента на порту 8767: `/api/language/status` возвращает версии платформы и активные снимки проектов; `/api/language/search?q=...&source=...&snapshot=...&scope=all&exact=0` возвращает отдельные группы `platform`, `metadata`, `code`; `/api/language/item?origin=...&id=...&source=...&snapshot=...` возвращает карточку; `/api/language/members?owner=Запрос&source=...` — члены платформенного типа. Требуется токен страницы `X-Athena-Token`. Код проекта читается через SQLite `mode=ro`; повторной выгрузки и пересчёта эмбеддингов нет. Служебные индексы имён сохраняются в `reference.sqlite3`, перестраиваются при изменении справки либо появлении нового снимка. Первый запрос строит эти индексы, последующие используют готовые.

Карточки платформы включают русские и английские имена, владельца, сигнатуру и текстовые разделы параметров/результата/доступности; карточки методов проекта — параметры, признак экспорта, хеш файла, строку и входящие/исходящие вызовы с качеством разрешения; карточки метаданных — свойства, дочерние элементы и модули. Определение типов переменных и интерактивное автодополнение относятся к следующему этапу. Свободный поиск по коду использует существующий FTS, без генерации моделью.

### Первоначальная настройка
При первом входе Athena открывает `/setup`: выбор нагрузки CPU/GPU, расширенные параметры ресурсов, необязательное подключение Ollama или OpenAI-совместимого API и проверка настроек. Мастер доступен повторно по ссылке «Настройка рабочего места» в шапке IDE. Завершение сохраняется локально в `.athena/user.json`; индексация остаётся приостановленной. API-ключ модели хранится только в памяти сервиса. Мастер не выгружает и не меняет базу 1С. После настройки пользователь выбирает проект в IDE.

### Установка GPU одной кнопкой
На первом шаге `/setup` кнопка «Настроить ускорение GPU» создаёт отдельное окружение `.athena/gpu-runtime`, устанавливает закреплённый `onnxruntime-gpu[cuda,cudnn]==1.31.0` и зависимости из PyPI и проверяет реальное вычисление MatMul на CUDA без CPU-подмены. Приложение остаётся в своём Python-окружении; GPU-инференс выполняет локальный дочерний процесс. Перезапуск сервиса не требуется. Установка требует Windows x64, Python 3.11+, NVIDIA-видеокарту, совместимый драйвер, интернет и несколько ГБ диска. Системный драйвер не устанавливается и не обновляется. Если проверка не прошла, показана ошибка; можно использовать CPU или повторить установку после обновления драйвера. Индексация и передача кода внешним сервисам при установке не запускаются. Ход установки показан в мастере; журнал `.athena/gpu-install.log`.

Установщик этой версии использует CUDA 13; перед скачиванием проверяет поддержку CUDA 13+ в драйвере NVIDIA. Для более старого драйвера предлагает обновление или работу на CPU. На RTX 5060 проверены пробный MatMul и получение векторов E5 через отдельный GPU-процесс.

Мастер теперь содержит отдельный шаг платформы 1С: автоматически найденные версии, ручной путь или «Обзор…», проверка существования 1cv8.exe и возможность настроить позже. Выбранный путь используется по умолчанию для новых подключений к базе. В шаге AI кнопка проверки запрашивает список моделей по текущим полям без сохранения профиля или ключа и без отправки кода. Индикатор GPU показывает четыре этапа; процент и объём скачивания относятся к текущему пакету из фактических данных pip. Для установки и проверки, где точный процент неизвестен, индикатор неопределённый.

Для переноса локального хранилища на другой диск можно использовать Windows junction для `.athena`: пути проекта, настройки и архивные ссылки остаются доступны через прежний путь. На текущем рабочем месте данные находятся в `G:\AthenaData\1C Athena AI\.athena`. GPU-установщик хранит pip-кэш в `.athena/pip-cache`, временные файлы — в `.athena/tmp/gpu-install`; кэш загрузки моделей Xet — в `.athena/xet-cache`.
## Инструменты агента

В AI-панели доступна ссылка «Инструменты агента» (`/agent-tools`): каталог 16 инструментов, проверка поиска и последние вызовы. Режим «Агент кода» использует этот API; режим «Вопрос по коду» сохраняет прежний поиск контекста и ответ.

Все маршруты требуют локального `X-Athena-Token`:

* `GET /api/agent/tools` — JSON Schema и описание инструментов. Для API модели используйте `tools.map(t => ({type:t.type, function:t.function}))`; поле `effect` служит интерфейсу Athena.
* `GET /api/agent/context` — проект, снимок, ревизия рабочей области, версии справки и готовность.
* `POST /api/agent/call` — `{call_id, tool, context:{project,snapshot,workspace_revision}, arguments}`. Возвращает `{ok,result,context}` или `{ok:false,error:{code,message}}`. `call_id` идентифицирует конкретный вызов; для изменённых аргументов нужен новый идентификатор.
* `GET /api/agent/history` — последние 50 успешных вызовов. Ограниченный кеш ответов (последние 1000 вызовов) хранится в `.athena/agent-tools.sqlite3`, включая возвращённые фрагменты кода. Повтор успешного вызова в этом окне возвращает сохранённый результат, в том числе после перезапуска.

`search` по умолчанию ищет код; `scope` выбирает код, метаданные или справку. Для `platform` и `all` обязательно явно выбрать `source` из контекста. Поиск использует общий лексический индекс. `get_symbol`, `get_calls`, `get_object`, `read_reference`, `read_module` возвращают ограниченные фрагменты и страницы. Вызовы с чужим проектом, устаревшим снимком или ревизией рабочей области отклоняются. Во время вызова смена проекта сериализована с работой инструмента.

Правка: `create_change_set` → `read_module` → `edit_module` → `validate_changes` → `show_diff` → `prepare_changes`. Передавайте актуальную `revision` набора и `expected_hash` текста. `read_module` с `set_id` читает текущий черновик; без него — сохранённый исходник. Замены `old_text` должны быть однозначными; вся последовательность либо сохраняется целиком, либо отклоняется. Если исходник изменился после создания черновика, автоматическая перезапись запрещена.

`create_object` принимает новый `Catalog`/`Document` с реквизитами, табличными частями, объектным и менеджерским модулями. `update_new_object` позволяет доработать предложенный объект, сохраняя его имя и вид. Изменение структуры существующих объектов пока не поддерживается. Подготовка проверяет BSL и конфликты, но не заменяет проверку конфигурации платформой 1С. Агент сохраняет только наборы и пакеты: загрузку выполняет пользователь через просмотр изменений в «Правках».

## Агент кода

Откройте AI → «Агент кода», задайте цель и выберите «Исследовать код» или «Предложить правки». Можно приложить открытый BSL-модуль и выбрать версию справки платформы. Подключение модели настраивается общей кнопкой «Настройки подключения»: Ollama или OpenAI-совместимый API. Нужна модель с нативной поддержкой вызова инструментов. API-ключ хранится только в памяти сервиса, поэтому после перезапуска его нужно ввести снова. Передача кода внешнему серверу требует сохранённого разрешения в настройках подключения.

В режиме предложений сервер создаёт отдельный набор для каждой задачи и сам подставляет его ID и ревизию в аргументы модели. Агент может читать код, метаданные, справку и связи вызовов, менять BSL-модули, проверять и готовить пакет. Создание объектов остаётся отдельным API этапа метаданных и в этом режиме модели пока не предоставляется. Режим исследования получает только инструменты чтения. Выполняются лишь нативные tool calls: произвольный текст ответа никогда не исполняется как команда или патч. Терминал, произвольные пути и загрузка в 1С отсутствуют в инструментах модели.

В интерфейсе видны шаги, результаты инструментов, затраченное время и переданные сервером счётчики токенов. Кнопка «Просмотреть предложения в Правках» открывает набор этой задачи. Финальный ответ модели сопровождается независимой локальной проверкой предложений; ошибки разбора выводятся отдельно даже если модель заявляет об успехе. Исходники файловой выгрузки остаются прежними до существующего пользовательского процесса загрузки и повторной выгрузки.

«Настройки агента» задают число шагов, вызовов инструментов, время, контекст и длину ответов. Контекст ограничивается меньшим из лимитов агента и подключения AI; старые пары вызов/результат удаляются целиком. Большие результаты сокращаются с явной пометкой. Это ограничение по символам, а не точный токенизатор модели. Агент прекращает работу при смене проекта, снимка, ревизии набора, трёх ошибках инструментов или достижении лимита. Правки пользователя не перебазируются автоматически.

Остановка блокирует следующие действия и поздний ответ модели. Уже сохранённые черновики остаются в наборе. Текущий HTTP-запрос завершается по ответу или тайм-ауту; до этого новый запрос AI не запускается. Автодополнение на это время использует локальные подсказки. Состояние и журнал задачи сохраняются в `.athena/agent-runs/*.json`, настройки — `.athena/agent.json`. После перезапуска незавершённая задача отмечается прерванной; автоматического продолжения или повторного применения нет. История интерфейса показывает последние 20 задач, полная история на диске сохраняется.

HTTP API, с обязательным `X-Athena-Token`: `GET /api/agent/status`, `GET /api/agent/job?id=...`, `POST /api/agent/start` (`goal`, `mode`, `context` из `/api/agent/context`, необязательные `file_id` и `source`), `POST /api/agent/cancel` (`id`), `POST /api/agent/settings` (полный объект настроек).

Протокол `auto` использует `/api/chat` для Ollama, Responses API для `api.openai.com` и Chat Completions для других совместимых серверов. При необходимости протокол API выбирается вручную. Реализованы нативные пары вызов/результат и сохранение служебных reasoning-полей между шагами согласно [OpenAI Docs: function calling](https://developers.openai.com/api/docs/guides/function-calling) и [Ollama: tool calling](https://docs.ollama.com/capabilities/tool-calling). Параметры конкретного совместимого сервера и качество выбранной модели нужно проверять на его подключении.
