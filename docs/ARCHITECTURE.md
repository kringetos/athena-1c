# Архитектура

## Основной поток

```text
Конфигуратор 1С → файловая выгрузка XML/BSL → Catalog
                                                 ↓
                                     Knowledge / SQLite / ANTLR
                                                 ↓
                         LanguageKnowledge ← Reference / справка .hbk
                              ↓          ↓             ↓
                         поиск      автодополнение   AgentTools
                                                         ↓
                                                  CodeAgent / модель
                                                         ↓
                                                   ChangeSets
                                                         ↓
                      просмотр пользователем → пакет → импорт → повторная выгрузка
```

## Карта кода

| Модуль | Ответственность |
| --- | --- |

## Инварианты, которые нельзя нарушать

1. Снимок знаний относится к одному проекту и версии исходников. Не смешивать методы разных снимков.
2. Перед записью учитывать хеш исходника, хеш текущего черновика и ревизию набора. При конфликте остановиться, а не молча перебазировать.
3. Модель предлагает изменения в своём наборе. Она не получает shell, произвольные пути, чужие наборы или импорт в 1С.
4. Пароли и ключи не записывать в Git, журналы, состояние задач и выдачу API. Внешняя передача кода требует настройки подключения.
5. Подготовка пакета не изменяет исходную файловую выгрузку. После импорта нужна повторная выгрузка и проверка результата.
6. Успех HTTP, ответ модели и отсутствие ошибок ANTLR не означают корректность конфигурации или бизнес-логики.
7. Остановка запрещает последующие действия после позднего ответа модели; новый запрос не создаётся поверх ещё работающего транспорта.

## HTTP и протокол инструментов

Сервис слушает loopback. API защищён `X-Athena-Token`, который выдаётся текущей странице, и проверкой локального обращения. Не переносите токен в URL или историю Git. Полный список маршрутов находится в `handler` модуля `server.py`.

Вызов инструмента передаёт `call_id`, `tool`, `arguments`, `context:{project,snapshot,workspace_revision}`. `AgentTools` проверяет JSON Schema и контекст; mutating-tools только изменяют набор/пакет. Ответы ограничены по размеру, большие коллекции выдаются страницами. Ограниченный кеш ответов обеспечивает повтор успешных вызовов в пределах сохранённого окна, но не является распределённой транзакцией.

`CodeAgent` предоставляет подмножество инструментов, привязывает записи к собственному набору и подставляет ID/ревизию. Общий каталог содержит 18 инструментов: исследование получает 9 инструментов чтения, предложения — 17; создание набора выполняет сервер автоматически. `create_object` и `update_new_object` доступны модели в режиме предложений. Успешные повторные чтения возвращаются из памяти; отсутствие новых фактов приводит к запросу итогового ответа без инструментов.

## Вопросы и документация

`POST /api/assistant/ask` направляет общие списки и структурные счётчики в обработчик XML-метаданных, остальные вопросы — в `CodeAgent` с режимом `analyze`. Кнопка «Найти контекст» использует поиск без генерации.

`Documentation` работает отдельно от цикла агента: собирает ограниченный контекст исходников, передаёт скилл и структуру шаблона существующему AI-транспорту и сохраняет черновик в `.athena/documents/<id>.json`. Выделение редактора передаётся с позициями UTF-16, хешем сохранённого файла и при необходимости локальным черновиком. Фрагмент или отдельный модуль должны помещаться целиком; покрытие проекта может быть неполным и отмечается явно. Перед публикацией результата проверяются контекст и хеши прочитанных модулей. Смысловая достоверность автоматически не сертифицируется.

Маршруты: GET `/api/documents`, `/api/documents/job?id=…`; POST `/api/documents/start`, `/api/documents/cancel`, `/api/documents/save`. Авторизация и разрешение внешней передачи кода общие с AI; запрос документации занимает общий слот генерации. Исходники и наборы изменений генератор не меняет.

## Хранение и процессы

Файловые выгрузки и артефакты находятся в `.athena`. Основная база знаний использует WAL и схему версии 2. Справка и журнал вызовов инструментов находятся в отдельных SQLite-файлах. Наборы и задачи сохраняются в JSON с атомарной заменой файлов; блокировки процесса не заменяют межпроцессную координацию.

IDE и справка — отдельные процессы; вычислитель GPU — отдельный дочерний процесс. UI не требует сборщика. Файлы справки и модели скачиваются/импортируются на машине пользователя и не поставляются через Git.
